# v0.3.41: убрано дополнительное ожидание после медленных ответов

В 0.3.40 к времени ответа Saby и записи добавлялась полная пауза 1,5–3 секунды. Теперь задаётся минимальный интервал между началами последовательных запросов. Время ответа, сохранения и выбора следующей продажи засчитывается в этот интервал. Одновременно выполняется только один запрос бонусов.

Например, при интервале 1,5 с:
- ответ и запись заняли 0,6 с → ожидание ещё 0,9 с;
- ответ и запись заняли 2 с → следующий запрос без дополнительной паузы;
- после задержки не выполняется серия догоняющих запросов: новая граница задаётся от фактического старта.

Это примеры расчёта, не замер скорости Saby. Фактический выигрыш зависит от времени ответов и БД. Предел частоты остаётся до одного старта в 1,5 с. Новый процесс начинает с интервала 3 с, после каждых 50 чистых успехов сокращает его на 0,25 с, минимум после 300 чистых успехов. Первый запрос может начаться сразу.

Ошибка увеличивает интервал и задаёт дополнительную задержку от момента ошибки, даже если ответ был долгим. Retry-After и распознанные блокировки соблюдаются отдельно; время медленного ошибочного ответа не вычитается из срока блокировки. При слишком длинном/неизвестном ожидании загрузчик останавливается с RETRY_LATER. Сохранённые ответы не перезагружаются, ошибки остаются в очереди.

В журнале bonus_progress: pacing_mode=START_TO_START и request_start_interval_seconds. Поле pause_seconds сохранено для совместимости, но означает настроенный интервал, а не фактическое дополнительное ожидание. resolved_per_hour и estimated_remaining_hours учитывают весь прошедший срок текущего запуска, включая повторы и запись; это оценка, не гарантия.

В plan: pacing=START_TO_START_ADAPTIVE_3_TO_1_5_SECONDS; minimum_wait_hours=null, потому что сумма дополнительных пауз заранее неизвестна. minimum_spacing_hours — теоретический нижний предел промежутков между стартами при 1,5 с, не оценка времени завершения. Длинные ответы, разгон и ошибки увеличивают срок.

После установки проверить 0.3.41:

```text
python -c "print(__import__('app.version', fromlist=['APP_VERSION']).APP_VERSION)"
python -m scripts.bonuses plan
```

Старый работающий процесс автоматически не меняет режим. После его штатной остановки/завершения и освобождения блокировки продолжить:

```text
python -m scripts.saby_data resume
```

Не снимать блокировку принудительно и не запускать второй загрузчик. Сохранённый прогресс остаётся в PostgreSQL. Полная загрузка заново и --refresh не нужны. Сервер автоматически не обновлялся.

Локальная проверка: 376 тестов пройдены, включая короткие/длинные ответы, отсутствие догоняющих всплесков, задержку после медленной ошибки и соблюдение ограничений. Реальную скорость проверяем по bonus_progress после установки.
