# Планы июля–сентября: дополнение к v0.3.8

В сборку v0.3.8 добавлены только scripts/import_plans.py, файл утверждённых планов,
инструкция и тесты импорта. Версия приложения остаётся 0.3.8. Slow mode не требуется.

Подготовлено 64 правила: июль 20, август 22, сентябрь 22. Первый столбец исходной
таблицы принят как DAY, второй как NIGHT. Все дни недели — ALL. Каждое правило
ограничено первым и последним числом своего месяца; октябрь не заполняется.

Подтверждённое соответствие: ГОЗНАК → Шоссе космонавтов 115а (398),
МЕДОВЫЙ → Яблокова 14 (5598), КАМСКАЯ → Камская 2/1 (поиск точного названия
без учёта регистра/пробелов). Остальные point_id взяты из предыдущих reconcile.
Для Камской за июль и РЦ планы отсутствуют в исходных данных и не создаются.

После развёртывания предварительный просмотр:

```bash
python -m scripts.import_plans
```

Ожидаем total=64 и to_insert=64 для новой базы планов. Проверьте соответствие магазинов
и сумм. Если всё соответствует присланной таблице, загрузите:

```bash
python -m scripts.import_plans --apply
```

Все вставки в одной транзакции. Повтор пропускает идентичные активные ALL-планы.
Несовпадающие/пересекающиеся ALL-планы и неизвестный магазин останавливают весь импорт
без частичной записи. Старые планы не перезаписываются. Weekday overrides сохраняются
и имеют прежний приоритет над ALL; в предоставленной таблице их нет.
Команды используют существующее окружение и выполняют штатную инициализацию схемы.

Проверка в Telegram:

```text
/plan Батумская 5 | 2026-07-10 | DAY
/plan Батумская 5 | 2026-09-10 | NIGHT
/payrollpreview 2026-09-19
```

Первые два результата: 20 000 ₽ и 65 000 ₽. Зарплатный расчёт остаётся предварительным
по учётке Saby до подключения фактического графика Core. Экзамены и политики не меняются.
Планы на сервере не записаны автоматически: для этого запустите команду --apply.
