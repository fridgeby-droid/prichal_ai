# Причал AI v0.3.20 — продажи по категориям

Категории здесь — разделы **каталога номенклатуры Saby**, а не разделы прайса
«ДОСТАВКА» и не классификация, придуманная языковой моделью. Получение и расчёты
выполняются программным кодом. AI только вызывает отчёт и объясняет результат.

## Что добавлено

- Полная загрузка текущего каталога с курсорной пагинацией и проверкой иерархии.
- Сопоставление товарных строк продаж с разделами по UUID или ID; без названий.
- Инструмент `get_category_sales`: продажи, возвраты, количества по единицам,
  сравнение периодов, крупнейшие изменения сумм товарных строк по категориям.
- `level=top` — верхний раздел; `level=leaf` — непосредственный раздел товара.
- «Без сопоставления» сохраняется в общей сумме и отдельно показывается в
  `unmapped_revenue` / `unmapped_product_groups`. Товар без раздела в самом
  каталоге — отдельная группа «Без раздела каталога», это не ошибка сопоставления.

## Настройка на сервере

Установите архив v0.3.20 и сохраните прежние переменные окружения. Новых ключей,
таблиц, миграции старых продаж или изменений Core не требуется.
Каталог сохраняется в существующей таблице `app_meta` схемы AI с отдельным ключом
`analytics:catalog_categories:v1`.

Сначала проверьте получение каталога без сохранения:

```text
python -m scripts.catalog_categories
```

Ожидается `complete_snapshot: true`, `mode: preview`, количество разделов и
товарных узлов, примеры путей разделов. Названия в примерах — из вашего каталога.
Секреты не выводятся. Проверьте, что это действительно нужные вам категории.

Затем загрузите справочник в AI:

```text
python -m scripts.catalog_categories --apply
```

Ожидается `mode: applied`. Заменяется только снимок категорий, продажи и прайсы
не меняются. `mode: superseded` означает, что уже сохранён более новый запуск.
После изменения каталога повторите команду. Автоматическое расписание загрузки
в этой версии не включается.

После загрузки можно написать боту:

> Сравни продажи по верхним категориям за 8–14 сентября 2026 и 1–7 сентября 2026.
> Покажи крупнейшие изменения и сумму без сопоставления. Проверь качество данных.

Или:

> Покажи продажи по непосредственным разделам товаров на Яблокова 14 за сентябрь 2026.

Если каталог не загружен, инструмент возвращает `catalog_status: NOT_LOADED`.
Продажи при этом не пропадают: все попадают в «Без сопоставления».

## Источник и ограничения

Официальный метод:
[`GET /retail/v2/nomenclature/list`](https://saby.ru/help/integration/api/app_sale/sale_delyvery/catalog/).
Запрос без `priceListId` получает каталог. Используются `order=after`, `position`,
`pageSize=25`, `noStopList=false`, `withBalance=false`, `withBarcode=false`.
Фотографии не нужны для категорий и не скачиваются. Права доступа определяются
существующей сервисной авторизацией Saby. Доступность полного каталога на вашем
аккаунте нужно подтвердить первой командой: успешная загрузка прайса 66 этого
не доказывает.

Полнота выгрузки подтверждается только после явного `hasMore=false` и проверки
графа. Повтор курсора, пропавший родитель, цикл, конфликт категорий одного товара,
неверные типы и превышение лимита страниц останавливают обновление.
Предыдущий снимок остаётся. Для HTTP 500 сохраняются ограниченные повторы.
Максимум страниц берётся из PRICE_LISTS_MAX_PAGES, общий тайм-аут — 600 секунд.

В отчёте используются суммы `sale_items.total_price` по бизнес-дате продажи.
Возвраты отдельно, отказанные позиции и удалённые продажи исключены, РЦ исключён.
Количество не складывается между разными единицами. Общая сумма по всем категориям
включает несопоставленные позиции; при ограничении вывода итог рассчитывается до
обрезки списка. `truncated` сообщает, что показаны не все категории.

**Классификация текущая, не историческая.** Если товар перенесли в другой раздел,
после обновления каталога старые продажи будут показываться в новом разделе.
Оба сравниваемых периода рассчитываются по одному сохранённому снимку в одной
read-only транзакции. В ответе есть время и revision каталога. Это не хранение
истории принадлежности товара к категориям.

Полнота продаж по-прежнему UNCONFIRMED. Сверку нужно вызывать отдельным инструментом
get_load_reconcile_status. Нет записей не означает нулевые продажи; изменение
категорий — вклад в изменение сумм товарных строк, не доказанная причина изменения
платёжной выручки. Разная длительность и незавершённые периоды отмечаются в ответе.

## Проверено

Автотесты проверяют порядок узлов, вложенность, одинаковые названия разделов,
ID/UUID, отсутствие связи, товары вне разделов, разные единицы, возвраты,
пагинацию, циклы/конфликты, сохранение только полного снимка и согласованное
сравнение периодов. Живая выгрузка каталога и результат на сервере ещё не проверены.

Существующие инструменты, API прайсов и справочников Core сохранены.
