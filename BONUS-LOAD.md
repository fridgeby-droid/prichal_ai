# Бонусы по сохранённым продажам — v0.3.31

## Загрузить всю локальную историю

Установите сборку на сервер с действующими настройками Saby и Timeweb. Выполните:

```console
python -m scripts.bonuses load --all
```

Команда читает бонусные данные всех сохранённых продаж без РЦ, включая возвратные записи. Даты не ограничены. Каждая продажа сохраняется отдельно. Минимальная пауза между продажами — 3 секунды: 1000 запросов занимают не менее 50 минут, 200 тысяч — около 7 суток, плюс задержки и повторные попытки. Сессия запуска должна оставаться работающей. Это ручной процесс, не фоновая задача сервера.

Остановка безопасна. Повторите ту же команду для продолжения. Уже обработанные неизменившиеся продажи пропускаются; ошибки повторяются. Новые продажи попадут в следующий запуск. Второй одновременно запущенный загрузчик отклоняется блокировкой PostgreSQL.

При HTTP 429/500/502/503/504 и сетевых сбоях выполняются ограниченные повторные попытки, учитывается ответ Saby о блокировке на 120 секунд. Если ошибка сохраняется, команда останавливается с кодом 1, сохранив прогресс. HTTP 404 также останавливает загрузку: это не нулевые бонусы. Пришлите итоговый код ошибки для разбора. Неизвестное направление операции и отсутствие UUID сохраняются как UNSUPPORTED и остаются неподтверждёнными; они не мешают другим продажам.

По умолчанию без --all обрабатываются до 100 записей. Для контрольного дня:

```console
python -m scripts.bonuses load --start 2026-10-23 --end 2026-10-23 --point-id 398 --all
```

Повторное чтение сохранённых ответов выполняется только с --refresh. После остановки такого запуска повторное --refresh заново читает и успешные записи; обычное продолжение без --refresh пропускает их. При изменении raw_json продажи её ответ перечитывается автоматически.

## Отчёт

```console
python -m scripts.bonuses report --start 2026-10-23 --end 2026-10-23 --point-id 398
```

Уберите --point-id для сети. Отчёт показывает известные списания, бонусы к начислению, среднюю платёжную сумму покупки с картой, отношение известных списаний к доступной платёжной выручке, число проверенных и неподтверждённых покупок. Покупка — уникальная продажа: несколько оплат не увеличивают знаменатель среднего чека. Возвраты исключены из этих показателей. Даты определяются по business_date продажи; это не отдельная сверка по времени платежей.

Списания выражены в баллах. Их отношение к рублёвой выручке не подтверждает курс баллов в рублях. При неполной проверке это отношение известных сумм, не итоговая доля всех списаний. Отсутствующие значения — null, не ноль. Начисление учитывается только из bonusInc; availableBonusInc не считается начислением. Банковская оплата не уменьшается повторно на бонусы.

## Хранение и ограничения

Добавлена таблица bonus_observations, уникальная по point_id + sale_id. Сохраняются только документированные бонусные поля, ID карт строками и время наблюдения. Контакты, токены и произвольные поля ответа не копируются. При ошибке прежний ответ сохраняется, но исключается из текущих показателей; это не архив всех версий ответа.

Источник: [Saby GET bonus-read](https://saby.ru/help/integration/api/app_sale/sale_bonuses/know_bonuses_off). Сопоставление Key с externalId проверено на двух контрольных чеках, универсальная применимость к остальным заказам требует наблюдения. Это не полный журнал карт: ручные начисления, сгорания, операции вне загруженных продаж и полный реестр клиентов не получены. Балансы относятся к моменту чтения; нельзя суммировать балансы разных продаж или считать их историческими остатками.

LOCAL_SALES_PROCESSED означает окончание обхода имеющейся базы, а не подтверждение полноты Saby. UNSUPPORTED и ошибки не доказывают отсутствие бонусов. Даже после завершения complete_history и source_complete остаются false.

Команды выполняются программным кодом, без LLM. API Core и существующие отчёты сохранены. Новые команды пока доступны в серверной консоли. Локально: 277 тестов пройдено; интеграция новой таблицы с рабочей PostgreSQL и массовый запуск Saby здесь не выполнялись.
