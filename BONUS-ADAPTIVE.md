# v0.3.39: постепенное ускорение бонусов

Локальная проверка: 373 теста пройдены, включая постепенное ускорение, замедление, распознавание ограничения в HTTP 500, соблюдение длительного Retry-After и оценку остатка без списания ошибок из очереди. Реальная скорость Saby ещё не измерена.

Все возможности v0.3.38 сохранены. Запросы последовательные, глобальная блокировка и сохранение каждого ответа не изменились. Уже сохранённые OK/UNSUPPORTED пропускаются, ошибки не превращаются в нули.

Пауза нового запуска 3 секунды. После каждых 50 успешных ответов без повторов — снижение на 0.25 с до минимума 2 с (200 чистых успехов для достижения минимума). Любая ошибка сбрасывает серию и увеличивает паузу на 1 с, максимум 10 с. При распознанном ограничении частоты пауза поднимается минимум до 6 с. Код HTTP 500 без маркера частоты не объявляется блокировкой.

Retry-After и текст ограничения Saby учитываются прежним механизмом: повтор не раньше указанного срока + запас, либо STOPPED/RETRY_LATER при неизвестном или слишком длинном ожидании. Такой запуск нельзя немедленно повторять: дождитесь снятия ограничения. Минимум 2 с — пробный предел этой версии, не обещание допустимой скорости API. Параллельность не добавлена. Новый процесс начинает снова с 3 с.

Каждые 25 обработанных продаж журнал bonus_progress содержит:
- pause_seconds — текущая пауза;
- resolved_per_hour — успешно обработанных/неподдерживаемых продаж в час текущего запуска, включая время запросов, повторов и сохранения;
- estimated_pending — начальная очередь минус разрешённые записи; ошибки остаются;
- estimated_remaining_hours — оценка при текущей скорости, после минимум 25 разрешённых записей. Для --refresh оценка срока не выводится.

Это не гарантия срока: новые продажи после начала запуска не включены в оценку, устойчивые ошибки могут остаться. При остановке и завершении эти поля также возвращаются. Метрики процесса не пишутся в отдельную таблицу: они доступны в его журнале и итоговом ответе.

`python -m scripts.bonuses plan` теперь показывает minimum_wait_hours как теоретический минимум пауз при 2 с и wait_hours_at_initial_3s для 3 с. Он не сообщает фактическую скорость работающего процесса: её смотрите в bonus_progress. При 50489 запросах это 28.05 и 42.07 часа только пауз соответственно; ответы, повторные запросы и запись добавляют время.

После установки проверьте версию и состояние загрузчика:

```text
python -c "print(__import__('app.version', fromlist=['APP_VERSION']).APP_VERSION)"
python -m scripts.bonuses plan
```

Ожидается 0.3.39. Действующий процесс сам на новый код не переключается. Не запускайте второй загрузчик при удерживаемой блокировке. После завершения/штатной остановки прежнего процесса и освобождения блокировки:

```text
python -m scripts.saby_data resume
```

Полная перезагрузка истории, --refresh и очистка БД для ускорения не нужны. Архив подготовлен локально, установка и проверка скорости на Saby выполняются отдельно.
