# Остатки, поступления и фактическая себестоимость — подготовленные изменения

Изменения включены в v0.3.54. На сервер версия автоматически не устанавливается.
Боевые ответы нужно проверить после установки новой сборки; в ранее выданном архиве v0.3.53 этих изменений нет.

## Что работает в коде

- `Товары → Себестоимость и маржа`: чтение фактической `TotalCost` из уже сохранённых продаж, без повторной загрузки чеков.
- `Товары → Наблюдения остатков`: последнее наблюдение каждого запрошенного товара/склада/организации внутри выбранного периода.
- `Товары → Нулевые остатки`: только явно полученные нули, с временем наблюдения. Отрицательный остаток — отдельная аномалия.
- Те же отчёты доступны агенту через `get_inventory_report` и в CSV. Отчёты не вызывают Saby.
- Явная загрузка снимков остатков по подтверждённой привязке и перечню ID товаров; ошибка/пропуск не меняет сохранённые наблюдения.
- Поиск поступления по точному номеру и дате с пагинацией, чтение структуры единственного найденного документа. Не выполняет документ и не скачивает вложения.

## Первая проверка на сервере после установки

Себестоимость Батумской за 13 ноября, локальные данные:

```sh
python -m scripts.inventory costs 2026-11-13 2026-11-13 --point-id 5635
```

Пример владельца: Батумская 5, поступление № УТ-121230 от 13.11.2026:

```sh
python -m scripts.inventory receipt --date 2026-11-13 --number УТ-121230
```

Команда ищет по аккаунту: фильтра по розничному point_id у этого метода нет. Совпадение номера **не доказывает** магазин. При нескольких совпадениях автоматического выбора нет. Вывод содержит ID/номер/дату/состояние и структуру документа, без контактов, ИНН, сумм, секретов и ссылок на вложения.

Справочники для привязки складов:

```sh
python -m scripts.inventory companies
python -m scripts.inventory warehouses COMPANY_ID
```

`COMPANY_ID` замените ID из ответа. Если формат неизвестен, команда показывает структуру; догадок о полях нет.
Используется существующая сервисная авторизация Saby. Ошибка 403 означает необходимость проверить права приложения; секреты в чат передавать не нужно.

## Остатки

Создайте локальный файл конфигурации по образцу ниже; фиктивные значения обязательно замените проверенными ID. `point_id` не является ID склада. Организация и склад привязываются явно; несколько складов не суммируются автоматически.

```json
{
  "mapping_confirmed": false,
  "point_id": "5635",
  "company_id": "ID_ОРГАНИЗАЦИИ",
  "warehouse_id": "ID_СКЛАДА",
  "products": {"ID_ТОВАРА": "шт"}
}
```

Единица — базовая единица складского учёта. Нельзя подставлять литры/упаковки без проверки коэффициентов. Поставьте `mapping_confirmed: true` только после проверки всех привязок.

```sh
python -m scripts.inventory stock-load data/stock-batumskaya.json
python -m scripts.inventory stock-load data/stock-batumskaya.json --apply
python -m scripts.inventory stock 2026-11-13 2026-11-14 --point-id 5635
python -m scripts.inventory stockouts 2026-11-13 2026-11-14 --point-id 5635
```

Предпросмотр не сохраняется. `--apply` выполняет новый запрос и атомарно сохраняет полный ответ по запрошенному набору. Создаётся только новая таблица `inventory_observations` и индекс. Продажи не изменяются. Каждое новое чтение — новое наблюдение, даже если количество совпало. Снимок не означает полный ассортимент склада; пропущенные товары не считаются нулевыми. Запросы пакетами по 25 ID с паузой 3 секунды.

Поддерживаемые формы ответа: массив строк `nomenclature/balance`, либо объект с массивом `balances` и, если есть `outcome`, явным `hasMore=false`. Это строгие поддерживаемые формы адаптера, **не подтверждение формы ответа вашего аккаунта**. Неподдерживаемый формат, повтор ID, неизвестное число, лишний/недостающий товар останавливают сохранение. Кодирование массивов запроса повторяющимися параметрами также требует проверки на аккаунте.

Автоматический опрос пока не включён: сначала проверяем ID, единицы и ответ. История начинается с первого наблюдения. Нельзя восстановить остатки сентября по сегодняшнему значению. Ноль доказывает отсутствие учётного остатка только в момент чтения, не физическое отсутствие на полке или непрерывную длительность простоя. Рост остатка не выдаётся за поступление: причиной может быть инвентаризация, перемещение или корректировка.

## Себестоимость и маржа

`TotalCost` берётся как сумма фактической себестоимости строки, **не умножается на количество**. Плановая `PlannedCost` никогда её не заменяет. Покрытие показано числом строк. Возвраты отдельно, по модулю. Неизвестное, некорректное и отрицательная стоимость обычной продажи — не ноль; явный ноль выделяется для проверки. Повтор одной строки в чеке не удваивает сумму; конфликт останавливает расчёт. Для вложенных позиций, комплектов и модификаторов распределение стоимости не выдумывается — они исключены и посчитаны в metadata.exclusions.

До согласования НДС показываются себестоимость и покрытие, маржа остаётся неизвестной. Подтверждение владельца, что Saby рассчитывает фактическую себестоимость, принято; оно не определяет включение НДС в конкретное поле.

Для проверенного магазина можно задать переменную окружения:

```env
COST_BASIS_BY_POINT={"5635":"same_as_total_price"}
```

Значение `same_as_total_price` допустимо только если фактическая себестоимость и TotalPrice на сопоставимой налоговой базе. `revenue_excludes_vat` — если из TotalPrice требуется вычесть явный TotalVAT для сопоставления с TotalCost. При отсутствии/некорректном TotalVAT эта строка не попадает в маржу. Для остальных магазинов база остаётся неподтверждённой; сетевой отчёт пока диагностический и не рассчитывает общую маржу.

Для разового проверочного расчёта есть `--cost-basis same_as_total_price` или `--cost-basis revenue_excludes_vat`. Агент не может выбирать базу самостоятельно.

Маржа = сопоставимая сумма продаж покрытых строк − фактическая себестоимость этих же строк. Процент = маржа / та же сумма продаж. Нулевая стоимость пока исключена из маржи: не подтверждено, бесплатный ли это товар или ещё не рассчитанная стоимость. Это не чистая прибыль: аренда, зарплата, комиссии и прочие расходы не загружены. Показатель не распространяется на строки без себестоимости, исключённые комплекты или всю платёжную выручку.

## Что ещё не завершено

Автоматическая загрузка товарных строк поступлений и подтверждение складского проведения ждут проверки ответа для УТ-121230. `СБИС.СписокДокументов` возвращает и черновики; статус ЭДО не равен складскому проведению. Пока нет проверенного источника движения, поступление не влияет на остатки или маржу. Вложения не читаются по произвольным ссылкам. Полнота исторических движений не заявляется.

После диагностического ответа потребуется проверить: ID документа и редакции, склад/организацию, статус проведения, товарные ID и единицы, даты принятия к учёту, отмены/корректировки, формат вложенных товарных строк. Неизвестный формат не заменяется пустой успешной выгрузкой.
