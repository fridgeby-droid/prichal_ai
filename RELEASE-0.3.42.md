# Причал AI 0.3.42 — независимые обновления Saby

## Установка

Заменить код приложения архивом и перезапустить приложение. Сохранить существующие
переменные окружения, секреты, настройки и собственный `data/analytics-rules.json`.
Базу не очищать; перенос старых данных и повторный bootstrap не нужны.
API Core, PostgreSQL/S3 и правила аналитики сохранены.

Проверка версии:

```sh
python -c "print(__import__('app.version',fromlist=['APP_VERSION']).APP_VERSION)"
```

На время ручных обновлений установить обе переменные в Bothost и перезапустить:

```env
AUTO_SYNC_ENABLED=false
AUTO_SYNC_ON_START=false
```

## Рекомендуемый порядок для текущей базы

Backfill №6 уже завершён. Повторять его не нужно. Выполнять команды по очереди:

```sh
python -m scripts.saby_data check
python -m scripts.saby_data stores
python -m scripts.saby_data catalog
python -m scripts.saby_data prices
python -m scripts.saby_data bonuses
python -m scripts.saby_data check
```

`stores` обновляет точки. `catalog` сохраняет полный новый каталог и категории.
`prices` обновляет список и содержимое всех доступных прайсов точек из
`SABY_PRICE_LIST_POINT_IDS` (в текущей конфигурации 23109). Новые прайсы также
обнаруживаются. Сохраняется только полный ответ; ошибка не заменяет прежний
снимок пустым. Полный успешно полученный пустой прайс сохраняется как пустой.
Исчезнувшие прайсы не удаляются из истории автоматически. Изображения в S3 Core
обновляются на стороне Core по существующему API; команда не загружает их в Core.

`bonuses` обрабатывает новые чеки с Customer, затем очередь ошибок.
Сохранённые OK/UNSUPPORTED ответы повторно не запрашиваются. Прежние 135 ошибок
не удаляются и не превращаются в нулевые бонусы. Новая загрузка может снова
остановиться при повторяющихся ошибках Saby.

## Продолжение после остановки

Каждый раздел имеет отдельный сохранённый прогресс:

```sh
python -m scripts.saby_data resume --component prices
python -m scripts.saby_data resume --component catalog
python -m scripts.saby_data resume --component bonuses
```

Выполнять только команду нужного раздела. Для stores и sales используется тот же
параметр. Завершённые прайсы текущего запуска при resume пропускаются. Повторная
команда `prices` после COMPLETED создаёт новое обновление и перечитывает прайсы.
Если отдельный запуск не завершён, сначала выполнить его resume. Ошибка в одном
разделе не запрещает начать другой. Одновременно работает только одно обновление
saby_data; отдельный загрузчик бонусов дополнительно защищён своей блокировкой.

Без `--component` команда resume продолжает прежний общий запуск. Она НЕ обновляет
его уже завершённые каталог и прайсы. Старый общий ERROR остаётся в check как
история этого запуска и не отменяет свежие результаты component_updates.

## Продажи

```sh
python -m scripts.saby_data sales --all-history
```

Проверяет покрытие от первой локальной продажи до последнего закрытого бизнес-дня
и загружает только непокрытые интервалы с недельной сверкой. Завершённые интервалы
пропускаются; текущий открытый день не загружается этой командой. Если база пустая,
указать явные --start и --end. sales также обновляет соответствия учёток продавцов,
но не запускает каталог, прайсы или бонусы. Пример явного диапазона:

```sh
python -m scripts.saby_data sales --start 2026-10-24 --end 2026-11-12
```

Общий `update --all-history` сохранён. Старый BONUS_LOAD_INCOMPLETE больше не
запрещает новый общий запуск: прежний результат архивируется в app_meta. Остальные
незавершённые общие этапы требуют resume. Бонусная неполнота теперь имеет статус
PARTIAL и код выхода 1, остальные завершённые этапы сохранены. Это НЕ заявление
полноты источника и НЕ скрытие ошибок.

## Статус и соединения

check не обращается к Saby. Выводит summary, component_updates, время обновления,
текущий этап, выполненные этапы, ошибки и сеансы с блокировками. RUNNING и idle сами
по себе не доказывают работу процесса; сравнивать счётчики и время двух проверок.
Отсутствие непокрытых дней подтверждает локальное покрытие backfill, не абсолютную
полноту Saby. Unsupported и ошибки бонусов остаются отдельными категориями.

Соединение блокировки backfill и длительных этапов maintenance проверяется каждые
30 секунд. Потеря соединения во время работы останавливает выполнение с
DATABASE_LOCK_SESSION_LOST; сохранённые блоки можно продолжить. Ошибка уже закрытого
соединения только при освобождении блокировки записывается как предупреждение и
не подменяет успешный итог загрузки. Произвольные ошибки работы не подавляются.

После ручных обновлений и отсутствия работающих загрузчиков можно вернуть
AUTO_SYNC_ENABLED=true для регулярных продаж. AUTO_SYNC_ON_START включать по
необходимости. Регулярная синхронизация продаж не означает автоматическое
обновление всех каталогов, прайсов и бонусов.

## Проверки

Автоматические тесты проверяют независимость разделов, продолжение прайсов,
сохранение прежнего снимка при неполном ответе, полный пустой прайс, архивирование
старого запуска, бонусную неполноту и обработку потери соединения блокировки.
Живые запросы к Saby и проверка на сервере пользователя не выполнялись.
