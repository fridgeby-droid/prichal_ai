# v0.3.28 — вложенные позиции продажи

В диагностике номера 25522 за 23.10.2026 найден внутренний ID 211800, магазин 398
(Шоссе Космонавтов 115а), закрытие 16:13 местного времени, BLACK QUEEN 1 л.
Внутри его Positions есть ещё одна строка. Прежняя диагностика и /modifiers
обрабатывали только верхние строки. Это исправлено.

## Проверка после установки

```text
python -m scripts.diagnose_sale 211800 --point-id 398
```

products теперь показывает все уровни Positions, path, line_key, parent_key,
названия и значения IsModifier. Номера карт, имена и контакты клиентов скрыты.
Не считать вложенную позицию тарой, пока не подтверждены название и признак:
в предыдущей диагностике значения вложенной строки не были раскрыты.
Время 16:13 расходится с первоначально указанным 16:22; это не исправляется предположением.

```text
/modifiers 2026-10-23 2026-10-23 point=398 query="тара"
```

Отчёт читает исходные raw_json уже загруженных продаж. Вложенность обходится
рекурсивно до 20 уровней; неправильная структура останавливает отчёт. История
не перезагружается, схема БД не меняется. Количество учитывается только при
явном IsModifier=true, не умножается повторно на количество родительского товара.
Отказ и возврат наследуются от родительской позиции/продажи.

Одинаковый SaleNomenclature (или Key при отсутствии ID) в одной продаже учитывается
один раз, даже если присутствует и сверху, и внутри Positions. Несовместимые
повторы останавливают отчёт вместо молчаливого выбора. Если нет обоих идентификаторов,
ключ строится по пути, и определить дубли разных путей нельзя. ID разных продаж не
смешиваются. Связь parent_key означает структуру переданного ответа, не отдельный
справочник связей каталога. Названия и количества не используются для склейки.

Неизвестное количество вызывает ошибку, не ноль. Если хотя бы у одной невозвратной
строки группы не указана сумма, сумма и средняя цена группы показываются как н/д;
количество при этом доступно. Нельзя прибавлять стоимость вложенных позиций к
выручке родительского товара: источник может уже учитывать её в сумме родителя.
Для модификаторов основной подтверждённый показатель — переданное количество.

Обычные /itemqty, /products, /basket и категории сохраняют прежний охват таблицы
sale_items (верхние строки), чтобы не менять выручку и не удвоить суммы вложений.
Для вложенных модификаторов используйте отдельный /modifiers. Нормализованная
отдельная таблица дерева ещё не создана; для больших периодов чтение raw_json
может быть медленнее, начинайте с одного магазина и дня.

Клиент в найденной октябрьской продаже указан, но явных полей начисления 9 баллов
в предоставленной структуре нет. Исправление не добавляет вымышленных бонусных
операций и не объявляет баланс нулевым. Подтверждение бонусного источника остаётся
отдельной незавершённой частью задачи.

Исправление HTTP 500 из v0.3.27 сохранено. Рабочие данные и сервер при подготовке
архива не изменялись; установка выполняется отдельно.
