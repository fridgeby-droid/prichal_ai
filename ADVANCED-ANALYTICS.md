# Дополнительная аналитика — включена в v0.3.38

Новый пакет находится в analytics-next-work и включён в архив v0.3.38. На сервер автоматически не установлен. Существующие отчёты и API сохранены. Новые отчёты не обращаются к Saby и не меняют БД. Telegram: только разрешённые пользователи; AI: get_advanced_report; консоль: scripts.advanced_report. Полный список дополнений — RELEASE-0.3.38.md.

## Команды Telegram

Общий формат: `/analytics ВИД НАЧАЛО КОНЕЦ point=ID offset=0 csv=true`.
point необязателен (сеть без РЦ), csv по умолчанию false, страница 50 строк.

| Задача | Пример |
|---|---|
| Разложение изменения суммы продаж | `/analytics decomposition 2026-09-01 2026-09-30 previous_start=2026-08-01 previous_end=2026-08-31` |
| Часы и дни недели по магазинам | `/analytics hours 2026-09-01 2026-09-30 point=398` |
| Совместные покупки товаров | `/analytics copurchases 2026-09-01 2026-09-30 point=398 min_pairs=3` |
| Новые и возвращающиеся клиенты | `/analytics customers 2026-09-01 2026-09-30` |
| Месячное удержание | `/analytics retention 2026-07-01 2026-09-30` |
| Возвраты по магазинам, учёткам и товарам | `/analytics returns 2026-09-01 2026-09-30` |
| Явные скидки и средние фактические цены товаров | `/analytics discounts 2026-09-01 2026-09-30 point=398` |
| Необычные изменения | `/analytics anomalies 2026-10-01 2026-10-23` |

Следующая страница: та же команда с offset=50, затем 100. CSV выгружает все строки выбранного отчёта. Смешанные разделы returns/discounts имеют разные поля; цены и возвраты товаров идут после сводки. Не суммировать разделы между собой.

Консоль, например:

```text
python -m scripts.advanced_report hours 2026-09-01 2026-09-30 --point-id 398
python -m scripts.advanced_report decomposition 2026-09-01 2026-09-30 --previous-start 2026-08-01 --previous-end 2026-08-31
python -m scripts.advanced_report copurchases 2026-09-01 2026-09-30 --point-id 398 --min-pairs 3 --csv pairs.csv
```

## Определения и ограничения

- Этот пакет использует **суммы уникальных продаж TotalPrice**, а не платёжные записи. Существующие отчёты платёжной выручки сохраняют прежний смысл. Средняя покупка = сумма / число уникальных продаж; возвраты отдельно.
- Разложение симметричное: вклад числа покупок = ΔN × (A0+A1)/2; вклад средней покупки = ΔA × (N0+N1)/2. В сумме даёт Δсуммы. При отсутствии покупок с любой стороны вклады неизвестны. Это арифметика, не причины. Среднее в день не исправляет изменение состава магазинов, календаря и пропуски.
- Часы: sale_datetime в business_tz; день недели из business_date. Часы 00–07 относятся к предыдущему бизнес-дню. Показаны число календарных дней нужного типа и дни с записями; отсутствующие часы не заполнены нулями. Без корректного времени час неизвестен.
- Совместные покупки: одна пара стабильных ID один раз на продажу; повторные строки не увеличивают счётчик. В знаменателе все покупки, включая покупки без строк. Возвраты и явные модификаторы исключены. support/confidence/retention и прочие доли — 0…1, не проценты. lift = P(A,B)/(P(A)×P(B)), не причинный эффект. Неизвестные ID не участвуют в парах; их число в metadata. Корзины больше 100 разных товаров останавливают расчёт, а не молча обрезаются.
- Новые клиенты впервые наблюдаются в доступной истории выбранной области. История до начала периода учитывается. Без Customer в сегментацию не входят. Фильтр магазина делает «первое наблюдение» первым в этом магазине.
- Когорты по месяцу первого наблюдения, месяцы от начала выбранного месяца до месяца отсечения. Месяц 0 означает активность исходной когорты, не повторный визит. Неполный календарный месяц показывает наблюдаемое число активных, но retention=null. Закрытый месяц не означает подтверждённую полноту Saby.
- Возвраты относятся к дате возврата. Отношение суммы возвратов к продажам периода не является долей исходных чеков, которые вернули. Связь возврата с исходной продажей не восстановлена.
- Скидки берутся только из явно сохранённого raw_json.TotalDiscount; отсутствующее поле неизвестно, даже если нормализованная колонка по умолчанию 0. Название скидки не доказывает бонусное списание. Средняя цена товара — сумма / количество в одной единице; без прайса и себестоимости нельзя выводить процент скидки от прайса или прибыль.
- Аномалии: каждый магазин сравнивается с медианой до 8 предыдущих одинаковых дней недели; минимум 4 наблюдаемых дня; кандидат при отклонении от 30% по сумме, числу или средней покупке. Нулевые и отсутствующие базы не дают процента. Это прозрачная эвристика, не статистическая гарантия и не автоматическое оповещение. Дни без продаж не интерпретируются как закрытие или отсутствие товара.
- Все расчёты одного вызова читаются в repeatable-read, readonly. Полнота источника всегда false; последний статус загрузки не подтверждает полноту выбранного периода. Ограничения: период до 366 дней, до 500000 продаж и 1000000 строк, превышение останавливает отчёт. История клиентов читается до даты отсечения, аномалий — дополнительно 56 дней назад.
- Тесты выполняются локально на фикстурах; реальная PostgreSQL и сервер не проверялись. Бонусная очередь не затрагивается.
