# Причал AI v0.3.33 — проверка и обновление данных Saby

Правила владельца: старые чеки не исправляются; продажа без customer_id не имеет бонусной карты и бонусов. Запросы бонусов выполняются только для продаж с customer_id. Продажи без клиента остаются в выручке и чеках, но не в очереди бонусов.

## 1. Проверка без запросов Saby

```console
python -m scripts.saby_data check
python -m scripts.bonuses plan
```

Общая проверка показывает магазины, диапазон и количество локальных продаж, последний sync, снимок каталога, сохранённые прайсы, состояние общего запуска и очередь бонусов. sales_windows_without_completed_backfill — участки от первой локальной продажи до последнего закрытого бизнес-дня без подтверждённого завершённого backfill. Наличие чеков не доказывает полноту дня. Обычный sync, даже OK, не заменяет подтверждение завершённого backfill со сверкой; такой участок может потребовать однократного backfill. Проверка не запрашивает удалённые изменения и не подтверждает полноту источника.

## 2. Загрузить недостающее и обновить поддерживаемые справочники

Перед общим обновлением установите AUTO_SYNC_ENABLED=false и AUTO_SYNC_ON_START=false, чтобы автоматическая загрузка не конкурировала с исторической. После завершения можно вернуть рабочие настройки. Общая команда:

```console
python -m scripts.saby_data update --all-history
```

Вся история означает диапазон от первой локальной продажи до последнего закрытого бизнес-дня. Из этого диапазона исключаются успешно завершённые и сверенные блоки backfill: старые дни заново не запрашиваются. Остальные участки загружаются по неделям с существующим reconcile. Состояние ERROR/RUNNING само по себе не обнуляет уже сохранённый прогресс блоков: учитывается next_date.

Для пустой базы или более ранней истории укажите диапазон явно:

```console
python -m scripts.saby_data update --start 2026-07-01 --end 2026-10-23
```

Без параметров update проверяет последние семь закрытых бизнес-дней. Текущий незавершённый день обрабатывается существующим auto sync, не этим backfill.

Порядок: магазины → недостающие продажи, платежи, позиции, смены и сверка → учётки продавцов → каталог категорий → список и полное содержимое прайсов разрешённых точек → бонусы всех локальных продаж с клиентом. Модификаторы и данные клиентов, доступные в продажах, поступают в сохранённом raw_json вместе с продажами; отдельного неподтверждённого API клиентов не вызывается.

Повторные сохранения используют существующие upsert и уникальные ключи. Каталог заменяется только после полной успешной выгрузки. Прайсы сохраняются в app_meta под maintenance:price:* только после успешного полного чтения. Ошибка не удаляет предыдущий снимок. Прайсы, исчезнувшие из нового списка, сохраняются как старые снимки: это не команда очистки Core. Используются только точки из SABY_PRICE_LIST_POINT_IDS; без настройки будет явное предупреждение PRICE_POINTS_NOT_CONFIGURED.

## 3. Продолжить после остановки

```console
python -m scripts.saby_data resume
```

Успешные этапы пропускаются. Для продаж продолжается тот же backfill, для бонусов используется их сохранённая очередь. Повторный update при незавершённом запуске запрещён — используйте resume. При ошибке команда заканчивается кодом 1 и сохраняет current_stage. После исправления повторите resume. Для сверки конкретного backfill можно использовать scripts.bootstrap reconcile-report с run_id из sales_windows.

Новый update после COMPLETED создаёт новый обход: завершённая история продаж и бонусы снова пропускаются, изменяемые справочники перечитываются. Без удалённого чтения нельзя определить, изменились ли каталог и прайсы. Между получением данных и сохранением отметки этапа возможен повтор после аварии; операции идемпотентны.

## Только бонусы

```console
python -m scripts.bonuses load --all
```

По предоставленной оценке будет около 54 626 запросов вместо 181 297 (число изменится с новыми продажами). При паузе 3 секунды это не менее 45,5 часа плюс ответы и повторы. Уже сохранённые ответы не читаются повторно. Для отложенных начислений и намеренной проверки состояния бонусов остаётся отдельная команда --refresh с узким периодом. Правило неизменности чеков не означает неизменности баланса карты.

## Границы «всех данных»

Обновляются все перечисленные поддерживаемые источники. Это не выгрузка всей учётной системы Saby. Полный журнал карт, ручные бонусные операции и самостоятельный полный реестр клиентов пока не реализованы. Фото прайсов представлены метаданными и способом скачивания существующего API; массовое сохранение файлов и миниатюр в S3 Core выполняет Core. Общая команда не меняет API Core и не отправляет данные в Core автоматически. Планы, зарплатные правила и график Core не относятся к источникам Saby и не перезаписываются.

Секреты не передаются в аргументах. Команды выполняются кодом, без языковой модели. Контакты клиентов и ключи Saby в общей сводке не печатаются. Состояние COMPLETED означает завершение заданных этапов, а не гарантию полноты всего Saby. Запуск вручную требует работающей серверной сессии.

Локальные тесты проверяют фильтр клиентов, сохранение выручки без карты, расчёт недостающих периодов, продолжение этапов, остановку на ошибке сверки и сохранение остального поведения. Установка, миграции и массовая загрузка на рабочем сервере здесь не выполнялись.
