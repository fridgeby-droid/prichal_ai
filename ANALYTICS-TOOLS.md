# Инструменты аналитики Причал AI v0.3.19

Шесть инструментов подключены к существующему AI-помощнику в Telegram.
Пользователь пишет обычный вопрос; AI выбирает инструмент и объясняет результат.
Расчёты выполняет Python/PostgreSQL, не языковая модель. Новых HTTP-маршрутов
для Core в этой версии нет. Существующие прайсы, справочники, график и S3 сохранены.

| Инструмент | Назначение |
|---|---|
| `list_stores(query)` | Локальный справочник: точный ID, название и адрес; неоднозначные совпадения требуют уточнения |
| `get_period_summary(date_from, date_to, point_id)` | Выручка, платёжные чеки, средний чек и возвраты, сеть и магазины |
| `compare_sales_periods(date_from, date_to, previous_from, previous_to, point_id)` | Изменения сумм и процентов по сети и магазинам |
| `get_day_night_breakdown(date_from, date_to, point_id)` | DAY/NIGHT по времени платежа, в целом и по магазинам |
| `get_product_sales(date_from, date_to, point_id, previous_from, previous_to, limit)` | Топ товаров или крупнейшие абсолютные изменения товарных сумм |
| `get_load_reconcile_status(date_from, date_to, point_id)` | Состояние sync, возраст последней успешной загрузки пересекающегося периода, отсутствующие магазин-даты и сверка |

Даты — YYYY-MM-DD, обе границы включены. Пустой point_id означает сеть.
Для конкретного магазина нужен точный ID из list_stores; поиск по имени выполняется
отдельно. РЦ (23109) исключён из всех розничных запросов, но остаётся доступен для прайсов.
Период — до 92 дней. Сверка выполняется блоками не более 7 дней: она восстанавливает
ожидаемые смены и тяжелее обычной сводки. Товарный ответ ограничен 1–50 группами;
`total_groups` и `truncated` сообщают об ограничении результата.

## Примеры вопросов боту

- «Покажи магазины и их ID».
- «Дай сводку сети с 1 по 7 сентября 2026: выручка, чеки, средний чек и возвраты».
- «Сравни 8–14 сентября 2026 с 1–7 сентября 2026. Какие магазины дали рост и падение?».
- «Для Яблокова 14 сравни DAY и NIGHT за эти два периода».
- «Какие товары сильнее всего изменились по сумме продаж между этими периодами?».
- «Проверь загрузку и сверку за 1–7 сентября 2026».

AI получает текущее время в BUSINESS_TZ для определения относительных дат.
Для воспроизводимой проверки лучше указывать год и точные границы.

## Определения и ограничения

- Бизнес-день — от настроенного BUSINESS_DAY_START_HOUR (сейчас 08:00)
  до того же часа следующего дня в BUSINESS_TZ. DAY/NIGHT берётся из платёжного слоя.
- Выручка = сумма абсолютных сумм невозвратных платежей; возвраты отдельно.
  Чеки = количество записей платёжного слоя, как в существующих отчётах и reconcile.
  Это не число уникальных sale_id. Средний чек = общая выручка / общее число таких записей,
  не среднее средних по магазинам.
- Нулевой знаменатель даёт null для процента. Когда в одном из сравниваемых
  периодов вообще нет записей, изменения не рассчитываются (null).
- Незавершённые периоды, разная длительность и отсутствие данных отмечаются.
  Сравнение сети включает доступные записи каждого периода; это не автоматически
  сравнение одинакового состава работающих магазинов.
- Полнота помечается UNCONFIRMED: в текущей БД нет надёжного журнала полноты
  по каждой точке и дню. Нет записей — не доказательство нулевых продаж.
  Исторический магазин мог ещё не открыться: его отсутствие тоже требует проверки.
- В сводках сверка NOT_CHECKED. Отдельный инструмент вызывает действующий
  reconcile и возвращает OK/REVIEW/NO_DATA. Даже OK подтверждает согласованность
  локальных фактов, не полноту источника. Правило длинных смен под учёткой Saby сохранено.
- Сводка за один период читается в согласованной read-only транзакции. Два периода
  сравнения и отдельная сверка могут читаться последовательно во время синхронизации;
  при обновлении данных повторите отчёт после завершения sync.
- Товарный отчёт использует sale_items.total_price и бизнес-дату продажи. Он
  не дублирует строки через JOIN с платежами и не приравнивается к платёжной выручке.
  Возвраты и отказанные позиции не входят в сумму продаж. Возвраты показываются отдельно.
- Товары группируются по UUID или ID и единице. Одинаковые названия не склеиваются.
  При отсутствии ID позиции остаются отдельными; сравнение таких строк ненадёжно.
  Разные единицы не объединяются. Исчезновение позиции в выборке не доказывает
  прекращение её продаж без проверки полноты обоих периодов.
- **Категории доступны отдельным инструментом get_category_sales** после загрузки каталога (CATEGORY-ANALYTICS.md). Товарный отчёт не включает их автоматически.

## Установка и проверка

Установить архив v0.3.19 обычным способом, сохранить все действующие переменные
окружения и перезапустить приложение. Новых переменных и таблиц нет.
Затем отправить боту примеры вопросов выше на уже загруженном периоде и сопоставить
однодневную сводку с существующими `/daily` и `/reconcile`.

Локально проверяются SQL на контрольных данных, возвраты, границы, неоднозначность,
пустые данные, сравнение товарных групп и регистрация инструментов в агенте.
Серверная PostgreSQL и фактический вызов языковой модели в этих тестах не используются.
Доступ к новым инструментам остаётся за существующей проверкой разрешённых Telegram-пользователей.
