# v0.3.40: постепенное ускорение бонусов до 1,5 секунды

Обновление 28.10.2026: минимальная пауза снижена с 2 до 1,5 с. Новый запуск начинает с 3 с; после каждых 50 чистых успехов снижает паузу на 0,25 с. Минимум достигается после 300 чистых успехов. Ошибки, ограничения Saby, последовательная обработка и сохранение прогресса работают по прежним правилам. Это пробная скорость, не подтверждённый лимит Saby.

Для последней известной очереди 49785 запросов минимум пауз составляет 20,74 ч вместо 27,66 ч при 2 с (на 25% меньше пауз). Реальное время выше: ответы, запись, повторы, разгон и замедления также занимают время. Текущий размер очереди проверяйте заново.

В plan: minimum_pause_seconds=1.5 и pacing=ADAPTIVE_3_TO_1_5_SECONDS_BACKOFF_UP_TO_10. Это настройки нового кода, а не подтверждение режима уже работающего процесса. Реальный режим виден по pause_seconds в bonus_progress. После установки версия должна быть 0.3.40. Не запускайте второй загрузчик и не снимайте блокировку: новая скорость применяется при запуске нового процесса после завершения/штатной остановки предыдущего.

Локальная проверка: 374 теста пройдены, включая постепенное ускорение, замедление, распознавание ограничения в HTTP 500, соблюдение длительного Retry-After и оценку остатка без списания ошибок из очереди. Реальная скорость Saby ещё не измерена.

Все возможности v0.3.38 сохранены. Запросы последовательные, глобальная блокировка и сохранение каждого ответа не изменились. Уже сохранённые OK/UNSUPPORTED пропускаются, ошибки не превращаются в нули.

Любая ошибка сбрасывает серию и увеличивает паузу на 1 с, максимум 10 с, с возвратом как минимум к 3 с. При распознанном ограничении частоты пауза поднимается минимум до 6 с. Код HTTP 500 без маркера частоты не объявляется блокировкой.

Retry-After и текст ограничения Saby учитываются прежним механизмом: повтор не раньше указанного срока + запас, либо STOPPED/RETRY_LATER при неизвестном или слишком длинном ожидании. Такой запуск нельзя немедленно повторять: дождитесь снятия ограничения. Параллельность не добавлена. Новый процесс начинает снова с 3 с.

Каждые 25 обработанных продаж журнал bonus_progress содержит:
- pause_seconds — текущая пауза;
- resolved_per_hour — успешно обработанных/неподдерживаемых продаж в час текущего запуска, включая время запросов, повторов и сохранения;
- estimated_pending — начальная очередь минус разрешённые записи; ошибки остаются;
- estimated_remaining_hours — оценка при текущей скорости, после минимум 25 разрешённых записей. Для --refresh оценка срока не выводится.

Это не гарантия срока: новые продажи после начала запуска не включены в оценку, устойчивые ошибки могут остаться. При остановке и завершении эти поля также возвращаются. Метрики процесса не пишутся в отдельную таблицу: они доступны в его журнале и итоговом ответе.

`python -m scripts.bonuses plan` показывает minimum_wait_hours как теоретический минимум пауз при 1,5 с и wait_hours_at_initial_3s для 3 с. Он не сообщает фактическую скорость работающего процесса: её смотрите в bonus_progress.

После установки проверьте версию и состояние загрузчика:

```text
python -c "print(__import__('app.version', fromlist=['APP_VERSION']).APP_VERSION)"
python -m scripts.bonuses plan
```

Ожидается 0.3.40. Действующий процесс сам на новый код не переключается. Не запускайте второй загрузчик при удерживаемой блокировке. После завершения/штатной остановки прежнего процесса и освобождения блокировки:

```text
python -m scripts.saby_data resume
```

Полная перезагрузка истории, --refresh и очистка БД для ускорения не нужны. Архив подготовлен локально, установка и проверка скорости на Saby выполняются отдельно.
