# TrafficBot: подготовка к подключению счётчиков

## Проверенный пример

trafficbot_Счётчик-1_2026-10-17_14-48-02.csv: Windows-1251, разделитель табуляция, заголовок `Дата / Время / Событие / ID`. Несмотря на расширение CSV, это табличный текст с табуляцией.

26 событий, 15 входов и 11 выходов. Даты строк: **07.02.2026 и 17.10.2026**. Имя файла не определяет период. Нельзя считать эти две группы непрерывным наблюдением или выводить фактическую заполненность магазина из разницы 4.

Файл проверен офлайн. Магазин для примера неизвестен: тестовое значение point_id при проверке не сохранено и не является привязкой. Исходник не изменён; данные в БД не импортировались.

## Уже реализовано

```text
python -m scripts.traffic "путь-к-файлу.csv" --counter-id DEVICE --point-id STORE_ID --timezone Asia/Yekaterinburg --stream-id SERIES
```

Все четыре параметра обязательны. STORE_ID заменяется реальным числовым ID. SERIES обозначает непрерывную серию событий без сброса ID, DEVICE — стабильный идентификатор устройства. Для разных экспортов одной серии SERIES должен совпадать.

Команда только проверяет файл; нет подключения к БД/Saby. `--output normalized.json` сохраняет нормализованный документ для проверки и отказывается перезаписывать существующий файл. Кодировки UTF-8/BOM и CP1251, разделители табуляция, точка с запятой и запятая. Неизвестное событие, ошибочное время, конфликт повторного ID останавливают весь файл. Точные повторы внутри файла удаляются с подсчётом duplicate_rows. Неоднозначное время при смене часового пояса не угадывается. Бизнес-день начинается в 08:00.

Нормализованное событие: counter_id, point_id, stream_id, source_event_id (строки); occurred_at с часовым поясом; direction IN/OUT; business_date. Документ содержит SHA256 исходника, кодировку, даты, счётчики строк. Всегда `coverage_confirmed=false`, `conversion=null`, `status=VALIDATED_NOT_IMPORTED`.

## Следующий этап, пока не реализован

1. Справочник устройств: стабильный ID, магазин, часовой пояс, период действия привязки, версия настроек направления. Название файла не является идентификатором устройства.
2. Постоянное хранилище: уникальность `(counter_id, stream_id, source_event_id)`. Повторная загрузка совпадающего события — пропуск; изменённое событие с тем же ключом — конфликт, а не тихая перезапись. Полный файл валидируется до атомарного сохранения. История импортов по SHA256 и сопоставлению; одинаковый файл с иной привязкой требует проверки.
3. Подтвердить, сбрасываются ли ID после перезапуска/очистки. До этого SERIES назначается явно. Если устройство умеет выдавать глобальный UUID события, использовать его.
4. Отдельные интервалы работоспособности/простоя. Промежуток между первым и последним событием не подтверждает работу всё это время. Нужны heartbeat или подтверждённые интервалы от системы счётчиков.
5. Уточнить правила нескольких дверей/устройств, повторных входов, сотрудников, групп людей, направления и точность часов. Входы — не число уникальных посетителей.
6. После подтверждения покрытия считать по одним магазинам и одним временным окнам: входы, выходы, покупки, покупки/входы, сумма продаж/входы, разбивка по часам и DAY/NIGHT. Не использовать число payment rows как число покупок. Нулевые входы или неполное покрытие дают неизвестную конверсию, не 0%. Конверсия может превышать 100% и требует проверки методики, не обрезки.
7. Данные датчика не подтверждают полноту продаж и наоборот. Возвраты не считаются покупками для конверсии. Заполненность помещения требует исходного остатка людей и полного непрерывного потока входов/выходов; сейчас не рассчитывается.

До подключения нужны только несекретные сведения: какой счётчик относится к какому магазину, часовой пояс устройства, правила сброса ID и доступный формат подтверждения работы. Ключи и пароли в чат не нужны.
