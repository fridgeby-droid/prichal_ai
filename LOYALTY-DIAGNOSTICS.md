# v0.3.29 — сравнение сумм двух контрольных продаж

Подтверждены выборки точки 398 за 23.10.2026:
- Number 25529, Sale 211869: открытие 17:16:47, закрытие 17:18. Пользователь сообщил сумму 2171.70 и начисление 108. DiscountInfo пуст.
- Number 25576, Sale 212324: открытие 20:24:08, закрытие 20:28. Пользователь сообщил сумму 1750.15 и списание 36. DiscountInfo содержит одну запись Name, Value, PercentValue; их значения предыдущий отчёт скрывал.

Официальная документация определяет DiscountInfo как массив скидок, Value — сумму скидки, PercentValue — процент, Name — название:
https://saby.ru/help/integration/api/app_sale/get_sale_data
Поэтому ни любую скидку, ни разность суммы продажи и оплаты нельзя автоматически записывать как бонусную операцию.
API текущего баланса не подтверждает историческое начисление конкретной продажи:
https://saby.ru/help/integration/api/app_sale/sale_bonuses/balance_of_bonuses

После установки:
```text
python -m scripts.diagnose_sale 211869 --point-id 398 --money
python -m scripts.diagnose_sale 212324 --point-id 398 --money
```

Это чтение сохранённой БД, без запросов Saby и без изменений данных. Результат компактный:
TotalPrice, TotalDiscount, отдельные Amount/CashSum/BankSum/PayBank и выбранные поля DiscountInfo.
Денежные значения представлены десятичными строками, отсутствующие — null. Никакой суммы
начисления из цены не вычисляется. Списания пока UNCONFIRMED. Банковские поля разных представлений
не складываются. Клиент, карта, телефон, комментарии платежей не выводятся; из названия скидки
скрываются длинные номера, адреса и URL.

Проверка должна установить, совпадает ли Value с 36 и как называется скидка, а также отличить
сумму покупки от фактической оплаты. Одного совпадения числа недостаточно для универсального
правила импорта всех скидок как бонусов. Для накоплений и балансов ещё нужен подтверждённый
источник операций; пустой DiscountInfo не равен нулевому начислению.

Схема БД, загрузчик продаж и расчёты не меняются. Вариант без переустановки полной сборки:
заменить только scripts/diagnose_sale.py приложенным файлом в установленной v0.3.28.
Он использует существующий app.services.sale_tree. После замены доступны те же команды --money.
