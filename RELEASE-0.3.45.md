# Причал AI 0.3.45 — область отчёта и оформление

Установить архив и перезапустить приложение. Настройки автоматики из 0.3.44
сохраняются. Повторная загрузка Saby и очистка БД не требуются.

## Защита области расчёта

В инструментах периодической аналитики агента пустой point_id больше не означает
сеть по умолчанию. Для сети требуется явное значение network. Для магазина агент
ищет точку через list_stores и передаёт её ID во все разделы. Однозначно выбранный
магазин сохраняется в контексте одного запроса: если агент пропустит фильтр в
следующем инструменте, используется этот магазин. Контексты пользователей изолированы.
Неоднозначный поиск требует уточнения. Scope contract результата явно обозначает
сеть или магазин; несовпадение области основного/детального отчёта вызывает ошибку.

SQL уже применял фильтр point_id. По присланному тексту невозможно доказать точный
неверный вызов старого агента: трассы нет. Новый код защищает от молчаливого перехода
на сеть, но не заявляет, что прежние цифры Батумской перепроверены на сервере.
Прямые CLI и Telegram-команды сохраняют прежние аргументы; network нужен в
инструментах агента. Технические идентификаторы в БД/API не менялись.

## Товарный топ

Добавлены возврат количества, сумма возвратов и число уникальных покупок по товару.
Покупка определяется парой point_id/sale_id, повторные строки одного товара в
покупке не увеличивают счётчик покупок. Разные единицы остаются разными группами.
Суммы товарных строк не обозначаются платёжной выручкой.

## Оформление

Инструкция агента теперь задаёт короткий обзор: заголовок, один вывод, до четырёх
основных показателей, несколько крупнейших изменений и одна строка качества.
Технические ID и многократные предупреждения не нужны в обычном сообщении.
Диагностика и точные значения остаются доступными по запросу.

По умолчанию — пять лидеров. Если пользователь явно просит топ-20, агент должен
показать все 20, не обрезать запрос до пяти. CSV не обещается без созданного файла.
Пустые строки между строками таблиц убираются. Пользовательские подписи смен —
«Дневная смена» и «Ночная смена». В кодовых примерах DAY/NIGHT сохраняются.
В детальных текстовых отчётах названия смен также переведены; JSON enum не меняется.

Агенту явно запрещено выводить дату открытия из первой продажи, придумывать причину
NOT_CHECKED, смешивать месячные изменения со средними за день или переименовывать
сетевой результат в магазинный. Даты открытия из подтверждённого календаря можно
использовать как прежде. Полные диагностические report_text сохраняются; их
компактное изложение агентом зависит от запроса пользователя.

## Проверка на сервере

Повторить запрос про Батумскую за октябрь: топ-20 с количеством, суммой, возвратами
и покупками, затем пакет МАЙКА по учёткам. Заголовок и все разделы должны относиться
к одной точке. Затем повторить сравнение октября с сентябрём по сети без РЦ.

Локальные тесты проверяют передачу scope через инструмент, отклонение сетевого
результата для магазинного запроса, изоляцию запросов, дополнительные товарные
показатели и форматирование. Живые отчёты/ответы языковой модели на сервере не
проверялись — нужен повторный пользовательский запрос после установки.
