# v0.3.5 — сверка с учётом отнесения целой смены

Отчёт 1–7 июля показывает расхождение clock-day payments и целых смен:
например, Маршала Рыбалко 99 — −1 008 ₽ и два лишних чека в сменах 1 июля,
затем +1 008 ₽ и два недостающих чека 2 июля. Это соответствует смещению
между датами при исходном правиле целой кассовой смены. По агрегатам нельзя
идентифицировать конкретные чеки; новая сверка проверяет ожидание по фактам БД.

В исходном ShiftEngine native-смена получает общую дату/тип, прежде чем делится
по продавцам. Чеки после 08:00 могут остаться в ночной смене предыдущей даты.
Строгое сравнение такой смены с clock-day платежами давало ложный REVIEW.

Теперь reconcile заново рассчитывает ожидаемые суммы и число чеков по платёжным
фактам с теми же правилами отнесения. При этом он не читает сохранённые итоги
смен для вычисления ожидания и не изменяет данные. Сохранённые work shifts
сравниваются с ожиданием; реальные расхождения остаются REVIEW.

Новые поля:

- expected_work_checks / expected_work_revenue — ожидание по правилам целой смены;
- expected_vs_work — разница ожидаемой и сохранённой выручки;
- attribution_checks_delta / attribution_revenue_delta — ожидаемое смещение
  относительно чеков по строгому времени business day;
- payment_vs_work — прежняя сырая разница, сохранена для диагностики.

Для OK ожидаемые и сохранённые суммы должны различаться менее чем на 0,01 ₽,
число чеков совпадать; fallback, отсутствие продавца и смены REVIEW по-прежнему
блокируют продолжение. Проверка не подтверждает полноту независимого источника Saby.

## После обновления

Оба флага auto-sync оставьте false. Не очищайте БД и не создавайте новый запуск:

```bash
python -m scripts.bootstrap resume 1
```

Команда повторит загрузку проблемной недели, перестроит смены прежними правилами
и сохранит новый reconcile. Если останется REVIEW:

```bash
python -m scripts.bootstrap reconcile-report 1
```

Проверено 51 тестом: перенос через 08:00, парное смещение дат, лишние/недостающие
чеки и деньги, флаги качества, сохранение backfill checkpoint и повтор.
Правила построения/объединения смен сопоставлены с v0.3.1 по синтаксическому дереву:
не изменены. schema.sql, PayrollEngine и S3-клиент побайтно совпадают с v0.3.1.
Реальный результат после повторной сверки на сервере ещё не проверен.
