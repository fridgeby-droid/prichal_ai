# Причал AI → Core: прайс-листы Saby

Контракт v1, Причал AI v0.3.16, 20 октября 2026.

В v0.3.16 добавлена нормализация трёх форм одного адреса изображения:
`img?...`, `/retail/img?...`, `https://api.sbis.ru/retail/img?...`.
Они дают одинаковый ID изображения. Другие хосты, HTTP, перенаправления,
нестандартные порты и пути не разрешены. Фактический формат ссылки в прайсе 66
пока не получен; диагностическая команда теперь показывает безопасную классификацию
ссылки без её параметров. Исправление требует проверки на сервере.

В v0.3.15 учтён фактический ответ точки 23109 / прайса 66:
у товаров `isParent=null`, у разделов — boolean.
Явный `null` принимается как товар только с корректными ID, названием и единицей.
`isParent=true` исключается как раздел до проверки товарных полей, которые
у разделов могут быть null. Отсутствующий маркер и другие типы не принимаются.
Первая страница с этим форматом подтверждена диагностикой пользователя;
полный обход и скачивание фото после исправления ещё требуют проверки на сервере.

## Назначение и границы

AI передаёт опубликованный ассортимент Saby программным кодом, без LLM.
Core загружает его в фоне и хранит у себя. Открытие заявки работает исключительно
с локальными данными Core. Поставщики, шаги количества и интерфейс заявок реализуются
отдельно в Core. Эта сборка не меняет их и не рассчитывает цены.

Основа сборки — AI v0.3.13. API `/api/v1/core/directories`, синхронизация продаж,
PostgreSQL, S3 и интеграция графика сохранены. Новых таблиц и миграции данных нет.
Установка Core v1.7.15 либо другой версии на сервер в этой работе не проверялась.

## Подтверждённые методы Saby

- [Список прайсов](https://saby.ru/help/integration/api/app_sale/sale_delyvery/price/):
  `GET https://api.sbis.ru/retail/nomenclature/price-list`,
  `pointId`, `actualDate`, `page`, `pageSize`.
- [Состав прайса](https://saby.ru/help/integration/api/app_sale/sale_delyvery/catalog/):
  `GET https://api.sbis.ru/retail/v2/nomenclature/list`,
  обязательные для нашего сценария `pointId`, `priceListId`;
  `order=after`, `position` последней **исходной** записи, `pageSize=25`.
  Курсор используется для обхода документированных ограничений обычной
  постраничной выборки в 1000 записей и глубины вложенности.
- [Изображения](https://saby.ru/help/integration/api/app_sale/sale_delyvery/additional_information):
  `GET https://api.sbis.ru/retail/` + значение `images[]` вида `img?params=...`.
- [Подготовка публикации и авторизация](https://saby.ru/help/integration/api/app_sale).

Список содержит доступные точке прайсы на текущую дату в `BUSINESS_TZ`.
Это не выгрузка всех внутренних документов Saby: прайс должен быть доступен
Retail API и настроен для публикации. Используйте прайс выбранных наименований.
Фактическая доступность зависит от настроек и прав Saby.

Официальные JSON-примеры используют `priceLists` / `nomenclatures` и
`outcome.hasMore: true|false`. В таблице описания товаров `outcome` назван boolean,
но пример показывает объект; реализован строгий разбор примера.
Отсутствие массива или признака завершения считается ошибкой, а не пустым прайсом.
`noStopList=false`: товары из стоп-листа не исключаются.
`withBalance=false`, `withBarcode=false`. Полученные от Saby цены в Core не передаются.
Разделы `isParent=true` пропускаются; их курсоры учитываются.

## Настройки AI

Сохраните существующие переменные окружения. Добавьте:

```dotenv
CORE_PRICE_LISTS_API_KEY=<отдельный случайный секрет длиной не менее 32 символов>
SABY_PRICE_LIST_POINT_IDS=23109
PRICE_LISTS_MAX_PAGES=2000
PRICE_LISTS_TIMEOUT_SECONDS=240
```

Для нескольких точек: `SABY_PRICE_LIST_POINT_IDS=23109,5598`.
Пустой список закрывает API прайсов. Это отдельный список от `SABY_POINT_IDS`.
Точка 23109 (РЦ) разрешается для прайсов явно; она по-прежнему исключена из
розничной загрузки продаж и reconcile.

Ключ прайсов создайте отдельно от `CORE_DIRECTORY_API_KEY`; его область —
прайсы разрешённых точек и изображения. Действующий ключ справочников не расширяется.
Ключ и учётные данные Saby хранятся только на серверах. Не передавайте их в
браузер, URL, журналы, чат или клиентскую сборку.
При смене ключа прайсов старые `download_path` перестают работать: повторите
получение состава. Пользовательские настройки Core сохраняются по ID.

API не запускает фоновой загрузки само. Core планирует обновления и повторяет
временные ошибки с увеличением интервала. Не запускайте параллельные обновления
одного прайса. Для долгой выгрузки настройте тайм-аут прокси выше 240 секунд,
клиентский тайм-аут — выше прокси. Ограничение страниц не обрезает результат:
достижение лимита возвращает ошибку.

## Авторизация и маршруты

Базовый URL: `https://prichal-ai.bothost.tech`.
Все запросы выполняются сервером Core по HTTPS:

```http
Authorization: Bearer <CORE_PRICE_LISTS_API_KEY>
```

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/v1/core/price-lists?point_id=23109` | Все доступные прайсы указанной точки |
| GET | `/api/v1/core/price-lists/66?point_id=23109` | Полный ассортимент прайса |
| GET | `/api/v1/core/price-list-images/{reference}` | Файл по `download_path` из состава |

`point_id` обязателен. Нет маршрута получения всех точек одновременно:
Core запрашивает настроенные точки по очереди. РЦ может отсутствовать в
`/directories`, поэтому не выводите перечень разрешённых точек прайсов только
из розничного справочника.

## Примеры ответов

Ниже условные данные, не результат живого запроса прайса 66.

Список, HTTP 200:

```json
{
  "schema_version": 1,
  "complete_snapshot": true,
  "fetched_at": "2026-10-20T10:00:00+00:00",
  "source_updated_at": null,
  "actual_date": "2026-10-20",
  "point_id": "23109",
  "revision": "sha256-значение",
  "price_lists": [{"id": "66", "point_id": "23109", "name": "Прайс поставщика"}]
}
```

Состав, HTTP 200:

```json
{
  "schema_version": 1,
  "complete_snapshot": true,
  "fetched_at": "2026-10-20T10:01:00+00:00",
  "source_updated_at": null,
  "actual_date": "2026-10-20",
  "price_list": {"id": "66", "point_id": "23109", "name": "Прайс поставщика"},
  "revision": "sha256-значение",
  "product_count": 1,
  "folders_skipped": 2,
  "products": [{
    "id": "12345",
    "name": "Сыр",
    "unit": "кг",
    "images": [{
      "id": "sha256-идентификатор-ссылки",
      "download_path": "/api/v1/core/price-list-images/<подписанная-ссылка>",
      "content_sha256": null
    }]
  }]
}
```

Все идентификаторы передаются строками. Товарный `id` — поле `id` номенклатуры
Saby, не `hierarchicalId` и не название. В Core используйте уникальный ключ прайса
`(source_connection, point_id, price_list_id)`; ключ позиции —
`(source_connection, point_id, price_list_id, product_id)`.
`source_connection` — локальная связь Core с конкретным аккаунтом AI/Saby.
Название не является ключом, одинаковые названия допустимы.

`fetched_at` — завершение получения данных в UTC, а не время изменения в Saby.
Документированные методы не дают надёжного времени изменения каждого товара:
поэтому `source_updated_at=null`.
`revision` — SHA-256 нормализованных метаданных, стабилен при повторной загрузке,
меняется при изменении названия, единицы, состава или ссылки изображения.
Он **не подтверждает неизменность байтов фотографии по прежней ссылке**.

`complete_snapshot=true` означает, что все страницы успешно получены,
валидированы, финальный `hasMore=false` получен; прайс повторно найден после
обхода. Это не транзакционный снимок Saby: API не предоставляет snapshot token.
На время большой выгрузки желательно не редактировать прайс. При сомнениях
повторите загрузку; Core не должен применять более старый параллельный результат.

Подтверждённый пустой прайс: HTTP 200, `complete_snapshot=true`,
`product_count=0`, `products=[]`. Пустой список доступных прайсов сам по себе
не означает пустой ассортимент ранее выбранного прайса.
Исчезнувший или недоступный прайс возвращает 404, а не пустой состав.

## Ошибки

Ошибка выгрузки не содержит частичного массива:

```json
{
  "schema_version": 1,
  "complete_snapshot": false,
  "error": {"code": "SABY_RESPONSE_INVALID"}
}
```

| HTTP | Причина |
|---|---|
| 401 | Нет ключа / неверный ключ |
| 403 | `POINT_NOT_ALLOWED` |
| 404 | `PRICE_LIST_NOT_AVAILABLE`, недействительная ссылка изображения |
| 422 | Неверные параметры запроса |
| 502 | Ошибка Saby, некорректный ответ, повтор страницы/курсора, конфликт товара, лимит страниц, ошибка изображения |
| 503 | Ключ или разрешённые точки не настроены |
| 504 | Тайм-аут полной выгрузки / изображения |

Ошибки авторизации и валидации FastAPI могут иметь обычное тело `{"detail": ...}`,
а прокси может вернуть HTML. Core применяет данные **только** при HTTP 200,
валидном контракте версии 1, ожидаемых ID и `complete_snapshot === true`.
Любой другой ответ, обрыв JSON, отмена, недоступность сети — не основание удалять
или отключать товары. При ошибке сохраняйте предыдущий ассортимент.

## Фотографии и кэш Core

Core использует возвращённый относительный `download_path` на **своём настроенном
доверенном адресе AI**, с тем же отдельным Bearer-ключом. Не открывает эту ссылку
в браузере пользователя и не подставляет произвольный адрес из входных данных.
AI проверяет подпись ссылки и разрешённую точку, обращается только к документированному
`https://api.sbis.ru/retail/img?...`, добавляя свой сервисный `X-SBISAccessToken`.
Ключи Saby не выдаются Core. Перенаправления не выполняются.
Документация показывает адрес изображения, но не гарантирует анонимный доступ:
AI всегда использует серверную авторизацию. Живая проверка фотографии ещё необходима.

Успешный ответ изображения:

```http
HTTP/1.1 200 OK
Content-Type: image/jpeg
ETag: "<sha256-файла>"
X-Content-SHA256: <sha256-файла>
Cache-Control: private, no-cache
X-Content-Type-Options: nosniff
```

Разрешены JPEG, PNG, WebP, GIF; проверяются тип и сигнатура. Лимит — 10 МиБ.
Core дополнительно декодирует изображение, ограничивает размеры/число пикселей,
делает безопасную миниатюру и сохраняет оригинал/миниатюру в своём S3.
Проверка сигнатуры AI не заменяет безопасный декодер Core.

Core хранит `image.id`, SHA-256, ETag и свои S3-ключи. На очередной синхронизации:

1. Для новой ссылки скачивает файл; совпадающий SHA-256 позволяет повторно
   использовать существующий объект S3 и миниатюру.
2. Для прежней ссылки отправляет `If-None-Match: "<предыдущий sha256>"`.
   AI проверяет актуальность и возвращает `304` без файла либо `200` с новым файлом.
   Не пропускайте эту проверку только из-за прежней `revision` прайса.
3. AI держит ограниченный кэш в памяти (до 32 файлов / 32 МиБ на процесс)
   и использует валидаторы Saby `ETag` / `Last-Modified`, если они доступны.
   После перезапуска или вытеснения файл потребуется прочитать заново.
   Если Saby не отдаёт валидаторы, AI скачивает файл для проверки SHA-256;
   неизменившиеся байты между AI и Core повторно не передаются.
4. При ошибке скачивания сохраняет прежнее изображение и планирует повтор.
   Для нового товара без доступного фото показывает заглушку.
5. `images=[]` в успешном составе означает отсутствие фото в источнике.
   Ошибка скачивания не эквивалентна отсутствию фото.

Подписанная ссылка не заменяет Bearer-авторизацию, не содержит секретов Saby и
сохраняется после перезапуска AI. Её содержимое не является зашифрованным:
используйте только в серверной интеграции. Ротация ключа требует новых ссылок.
Неизвестный формат `images[]` останавливает выгрузку, не стирает фотографии.

## Обязательные правила импорта на стороне Core

Применять полный снимок в одной транзакции после проверки структуры и количества.
Повторная загрузка делает upsert по стабильным ID.

- Название, единица и список изображений обновляются из Saby.
- Поставщик прайса и индивидуальный шаг товара принадлежат Core и сохраняются.
- Общего шага для прайса нет. Новый товар недоступен в заявках до положительного
  подтверждённого шага.
- Изменение `unit` сбрасывает подтверждение шага. Core хранит подтверждённую
  единицу вместе с шагом; до нового подтверждения товар не добавляется в заявку.
- Количество, в том числе введённое вручную, проверяется сервером Core через
  Decimal: положительное и кратное шагу (например, 0.5, 1, 6). Не используйте float.
- Товар, отсутствующий в полном успешно полученном составе **этого прайса**,
  отключается только для новых заявок. История заявок и прежние настройки сохраняются.
- Неполная выгрузка, ошибка, отсутствие прайса в списке и 404 не очищают ассортимент.
- Изображения можно обрабатывать отдельно после транзакции ассортимента:
  ошибка фото не должна удалять прежний файл или тормозить открытие заявки.
- Обновления одного прайса сериализуйте. Поставщик определяется в Core,
  не выводится автоматически из названия прайса.

## Проверка на сервере AI

После установки архива и настройки двух новых переменных перезапустите AI.
Проверка использует уже сохранённые серверные секреты, без передачи их в команду:

```text
python -m scripts.price_lists 23109
python -m scripts.price_lists 23109 66 --check-image
```

Второй вызов выводит полноту, количество товаров, число пропущенных разделов,
ревизию и результат скачивания первой доступной фотографии (MIME, размер, SHA-256).
`--full` дополнительно выводит весь ассортимент; для обычной проверки не нужен.
Код возврата 1 означает ошибку, не пустой прайс. CLI ничего не меняет в БД.
Если ответ `PRICE_LIST_NOT_AVAILABLE`, проверьте публикацию прайса 66 для точки
23109 и его период действия. Если `SABY_RESPONSE_INVALID`, нужен обезличенный
пример структуры ответа; не присылайте токены.

После этого Core отдельно проверяет защищённые HTTP-маршруты: CLI проверяет
доступ к Saby, но не настройки публичного домена/прокси/Bearer на сервере.

## Проверено и ограничения

Автоматические тесты покрывают пагинацию свыше 1000 записей, разделы, пустой
ассортимент, повторную загрузку, изменение единиц/ссылок, исчезновение прайса,
некорректные и неполные ответы, ограничения страниц, отдельный ключ,
подпись и область доступа изображений, MIME/размер, условные ответы 304.
Существующие тесты AI также запускаются.

Живой запрос `23109 / 66` и фактическое скачивание фотографии с вашего Saby
локально не выполнялись: учётные данные доступны на сервере, а не в рабочей папке.
Проверка опубликованных методов и примеров не заменяет эту проверку.
API Core, S3 Core, шаги количества, интерфейс и установка на сервер не входят в архив AI.
