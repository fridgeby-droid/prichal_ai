# v0.3.26 — подтверждённый признак модификатора и уточнение продажи

Присланная диагностика внутренней продажи Sale=25522, point_id=398 содержит два объекта
SaleNomenclatures с числовым Quantity=1 и полем IsModifier типа bool. Значения IsModifier,
названия, даты и Number прежняя диагностика скрывала. Поэтому пока нельзя утверждать,
что выбран именно пример с 9 начисленными баллами и одной тарой 1 л.

В этом ответе Customer=null, CustomerName=null, DiscountInfo — пустой список;
явных полей бонусов не найдено. Это не означает, что начисления не было.

## Проверить номер, магазин и дату

После установки v0.3.26:

```text
python -m scripts.diagnose_sale --number 25522 --date 2026-10-23
```

Поиск идёт по raw_json.Number и календарной дате sale_datetime в часовом поясе проекта.
Он не подменяет Number внутренним Sale ID. При неоднозначности выдаются до 20 кандидатов
с магазином, ID, номером и датами; повторите с --point-id нужного магазина. При единственном
совпадении выводятся названия товаров, количества, единицы и реальные bool-значения IsModifier.
Контакты, имя клиента и номера карт по-прежнему не выводятся. Время может быть показано с UTC-смещением;
сверяйте с 23.10.2026 16:22 Asia/Yekaterinburg, учитывая часовой пояс.

Для проверки ранее найденного внутреннего ID:

```text
python -m scripts.diagnose_sale 25522 --point-id 398
```

Не назначайте магазину ID 398 по одному результату: новая диагностика покажет название из справочника.
NOT_FOUND означает отсутствие локального совпадения по этим условиям, не отсутствие покупки в Saby.
При несовпадении даты оплаты и даты исходной продажи можно проверить внутренний ID без фильтра даты.

## Отчёт по модификаторам

```text
/modifiers 2026-10-23 2026-10-23 query="тара"
```

Опционально добавьте point=ID, seller=ID, shift=DAY либо NIGHT, offset=50 для следующей страницы.
Идентификаторы продавца берите из /avgcheck. Для серверной команды:

```text
python -m scripts.detail_report modifiers --start 2026-10-23 --end 2026-10-23 --query "тара"
```

Читаются уже сохранённые sale_items.raw_json, только с явным JSON boolean IsModifier=true.
Строка "true", число 1, null и отсутствующий признак не приравниваются к true.
Количество — Quantity самой проданной строки, повторного умножения на количество основного
товара нет. Возвраты отдельно, отказанные строки и удалённые продажи исключены.
Группировка: точка, учётка продавца, стабильный ключ товара, единица. Повторный отчёт ничего
не записывает и не создаёт дублей. Для всей тары, включая обычные товары, используйте /itemqty.
Родительская связь модификатора не установлена и не выдумывается. Новых колонок и миграций нет.
Признак сохранялся в raw_json и раньше; заново загружать историю ради отчёта не нужно.

Бонусы ещё не нормализованы. Сначала нужно подтвердить правильную продажу по номеру/дате/товарам.
Если и в её ответе бонусов нет, потребуется проверить документированный источник бонусных операций
отдельно. Нельзя выводить баланс или 9 начисленных баллов из Customer, скидки либо суммы оплаты.
Клиентские сегменты v0.3.25 основаны только на наблюдаемых customer_id и не являются полной базой
владельцев карт; данный пример подчёркивает это ограничение.

Рабочие данные и сервер при подготовке сборки не изменялись. Установка и проверка настоящей продажи — отдельно.
