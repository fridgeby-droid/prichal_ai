# v0.3.4 — обработка пустого ответа Saby

В ответе аккаунта обнаружен orders: {}. Теперь он принимается как пустая выборка только при outcome.hasMore=false и отсутствии ошибки API. Missing/null и непустые объекты по-прежнему отклоняются. hasMore=true не позволяет завершить короткую страницу.

После обновления сборки с прежними настройками и выключенным auto-sync выполните:

```bash
python -m scripts.bootstrap resume 1
```

Не очищайте БД и не создавайте новый запуск. Если остановка повторится, отправьте строку SABY_RESPONSE_INVALID: теперь она также содержит фактическое булево значение has_more. Содержимое чеков и токены не выводятся.

Проверено 40 тестов. Реальная загрузка на Timeweb/Saby локально не выполнялась.
