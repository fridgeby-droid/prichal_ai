## Товары, модификаторы, доля покупок

В /itemqty и /modifiers добавлены итоги по каждому товару и единице для всей выборки и каждого магазина. Далее идёт прежняя разбивка по учёткам продавцов. Количества выводятся без лишних нулей, до 3 знаков после запятой; исходные Decimal и CSV сохраняют точность. Суммы разных единиц не объединяются.

Доля = уникальные невозвратные продажи с конкретным товаром / все невозвратные продажи выбранной области. В числителе одна продажа с двумя одинаковыми пакетами считается один раз. Для строки продавца знаменатель — покупки этого продавца в этом магазине; для итога магазина — все покупки магазина; для выборки — все покупки выборки. Атрибуция по продавцу и business_date продажи. Доли разных товаров нельзя складывать. Это не число фискальных чеков и не доля платёжных записей.

```text
/itemqty 2026-09-01 2026-09-04 point=5635 query="пакет МАЙКА" match=exact
/modifiers 2026-10-23 2026-10-23 point=398 query="тара 1" match=exact
/modifiers 2026-10-23 2026-10-23 point=398 query="019e8cc6-3fd2-76b3-a7ff-79e2e370d54a" match=id
```

match=contains (по умолчанию) — подстрока названия или ID; match=exact — полное название без учёта регистра; match=id — только ID/UUID, с допустимым префиксом id:/uuid:. Тёзки товаров с разными ID не объединяются. Неизвестные суммы модификаторов остаются н/д.

## Сравнение товаров

```text
/itemcompare 2026-09-01 2026-09-04 2026-08-01 2026-08-04 point=5635 query="пакет МАЙКА" match=exact
/itemcompare 2026-10-20 2026-10-23 2026-10-16 2026-10-19 point=398 query="тара 1" match=exact modifiers=true
```

Порядок аргументов: текущий период, база сравнения. В ответе база → текущий период. Показываются количество, возврат количества, сумма товарных строк, средняя фактическая цена, доля покупок с товаром и количество за календарный день. Сравнение по стабильному ID + единице, отдельно по магазинам; итоги сети доступны в JSON product_totals. При смене единицы строки не склеиваются. Отсутствие записи в периоде — н/д, не доказанный ноль. Периоды читаются последовательно из локальной БД; это не единый снимок двух запросов при одновременной перезагрузке продаж.

## Полный CSV

Добавьте csv=true к /itemqty, /modifiers, /clients, /itemcompare, /saleaudit или /client. Бот пришлёт файл только разрешённому пользователю. Он содержит все строки, а не одну страницу. Для карточки клиента CSV содержит магазины клиента; общая сводка и бонусное покрытие остаются в тексте/JSON карточки. Для товара CSV содержит разбивку по учёткам, включая знаменатель и долю; объединённые итоги доступны в тексте/JSON. Предел отправки — 45 МиБ; при превышении сузьте выборку. Значения, которые могли бы стать формулами Excel, экранированы. Неизвестное значение — пустая ячейка; completeness=false есть в каждой строке.

```text
/clients 2026-07-01 2026-10-23 min=30 max=59 csv=true
/itemqty 2026-09-01 2026-09-04 point=5635 query="пакет" csv=true
```

Серверная выгрузка (файл остаётся на сервере):

```console
python -m scripts.detail_report quantities --start 2026-09-01 --end 2026-09-04 --point-id 5635 --query "пакет МАЙКА" --match exact --csv packages.csv
python -m scripts.detail_report clients --start 2026-07-01 --end 2026-10-23 --min-days 30 --max-days 59 --csv clients.csv
python -m scripts.extra_report compare --start 2026-09-01 --end 2026-09-04 --previous-start 2026-08-01 --previous-end 2026-08-04 --point-id 5635 --query "пакет" --csv comparison.csv
```

## Карточка клиента и посещения

```text
/client 5688 2026-10-23
/clients 2026-07-01 2026-10-23 min=30 max=59 frequency=one_purchase
/clients 2026-07-01 2026-10-23 min=30 max=59 frequency=multiple_one_day
/clients 2026-07-01 2026-10-23 min=30 max=59 frequency=repeat_visits
```

Карточка клиента — история сети до указанной даты, без телефонов и ФИО клиента: первая/последняя покупка, давность, покупки, дни посещений, магазины, сумма TotalPrice невозвратных продаж, средняя сумма продажи и интервал между днями посещений. У клиента без истории показатели сумм/дат н/д.

Бонусный блок содержит число актуальных ответов из числа покупок, известные списания и к начислению, время последней попытки в JSON. Отсутствующие ответы не заменяются нулями; старый ответ с несовпадающим fingerprint не считается актуальным. Это не восстановленный баланс карты и не доказанный журнал проведённых начислений.

Три группы посещений не пересекаются: одна покупка; несколько покупок в один день; посещения в разные бизнес-дни. Группы считаются внутри выбранного интервала давности до применения фильтра frequency; это указано в ответе. Фильтр точки ограничивает историю посещений этой точкой; без точки — сеть.

## Средний чек и оплаты

Платёжное среднее и средняя сумма продажи подписаны отдельно; формулы не изменены. Нет автоматического признания платёжной строки фискальным чеком.

```text
/saleaudit 2026-10-23 2026-10-23 point=37462
```

Диагностика показывает продажи с несколькими или отсутствующими оплатами, либо расхождением даты/продавца/признака возврата между продажей и оплатами. Период учитывает дату продажи ИЛИ платежа, чтобы не потерять смещения границ. Выводятся внутренний ID, номер продажи, суммы, количество обычных/возвратных платежей и выбранные поля каждой оплаты. Это кандидаты для проверки, а не команда удаления дублей. Сырая JSON-продажа не выводится.

```console
python -m scripts.extra_report payments --start 2026-10-23 --end 2026-10-23 --point-id 37462 --csv payment-audit.csv
python -m scripts.extra_report customer --customer-id 5688 --end 2026-10-23
```

## Лёгкий статус бонусов

`scripts.bonuses plan`, `scripts.bonuses report`, `scripts.saby_data check` и новые диагностические CLI подключаются без выполнения схемы/DDL. База должна быть уже инициализирована приложением. Полный plan считает агрегаты в PostgreSQL и получает только итоговую строку, состояние блокировки и последние 10 ошибок. Исходные raw_json и их MD5 не читаются. Доступны last_attempt_at и last_success_at; они помогают увидеть продвижение между проверками, но не доказывают работу процесса в момент проверки.

changed_saved=null и freshness_checked=false означают, что дорогая сверка содержимого не выполнялась. pending_requests — оценка по наличию sale_key; UUID проверяется уже в загрузчике. Не называть этот счётчик точным числом валидных удалённых запросов. TimeoutError показывает этап database_connect/database_prepare/bonus_plan/saby_check и т. п. Тайм-аут проверки не равен остановке загрузки. Для существующих подключений лимит запроса остаётся 90 секунд.

## Фотографии

AI повторяет только временно неудачное скачивание конкретного изображения, максимум 3 попытки. 404, неподдержанный тип и чрезмерный размер не повторяются. Авторизация, запрет перенаправлений, лимит размера и проверка сигнатуры файла сохранены. При 429 возвращается рекомендация ждать 120 секунд. Ошибка изображения содержит retry_scope=image и refetch_price_list=false. Подробности для команды Core: CORE-IMAGE-RETRY.md.

Для независимой ручной проверки/скачивания изображений на стороне AI:

```console
python -m scripts.price_images prepare --point-id 23109 --price-id 82 --manifest price82-images.json
python -m scripts.price_images download --manifest price82-images.json --output price82-images
```

prepare один раз получает полный прайс и сохраняет приватный манифест. download повторно прайс не запрашивает, сохраняет файлы с хешированными именами и MIME в манифесте. Повторный download пропускает успешные файлы с совпавшей локальной контрольной суммой, повторяет ошибки/пропавшие/повреждённые файлы. --recheck принудительно перепроверяет изображения. Для обновления ассортимента создайте новый манифест другим именем. Запускайте один процесс на манифест. Это диагностика и локальное скачивание, не запись в S3 Core и не создание миниатюр.

## Инструменты AI и ограничения

get_detail_report расширен точным поиском и группами посещений. get_extra_report даёт сравнение товаров, карточку клиента и диагностику платежей. Все расчёты выполняет код; команды отчётов не обращаются к Saby. LLM получает ограниченную страницу результатов, CSV строится на сервере из полного списка.

Изменения пока только в этой рабочей папке. Действующий сервер, данные, Core и прежние архивы не изменены. Изменение стратегии повторов в Core требует реализации в его чате; AI не может заставить уже установленный Core прекратить повторную загрузку прайса. Локальные тесты не заменяют проверку новой SQL-диагностики на рабочей PostgreSQL и контрольных чеках.
