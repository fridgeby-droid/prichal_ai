# Отдельные покупки

## Покупки и бонусные карты (новый инструмент get_purchase_loyalty)

Примеры:
- Сколько покупок больше 500 рублей с бонусной картой было в октябре 2026 по сети?
- Сравни средний чек с картой и без карты в Батумской за октябрь 2026.
- Какая доля суммы покупок приходится на подтверждённые карты?
- Покажи покупки со списанием бонусов за октябрь в Батумской.
- Сколько покупок с бонусами к начислению у этой учётки продавца?
- Покажи покупки, для которых бонусные данные не подтверждены.

Порог суммы: gt/gte/lt/lte/eq; без порога — весь период до 92 дней. Фильтры магазина,
учётки, смены. Список по 20 покупок по убыванию суммы, с пагинацией. Из списка можно
перейти к get_purchase_card по point_id/sale_id. Новый CSV не реализован.

Карта подтверждается свежим OK-ответом bonus_observations с положительным cardId или
personalCardId. Свежесть — совпадение fingerprint с md5(raw_json::text), как в существующем
бонусном отчёте. Нет Customer — без карты по правилу владельца. Остальные случаи unknown.
Ответ без ID карты не считается доказательством отсутствия карты. Ошибки не маскируются нулями.

Суммы и средние — TotalPrice покупок, не платёжная выручка. Доли рассчитаны от всех
покупок, прошедших фильтры периода/магазина/суммы/учётки/смены, включая unknown.
Группы карт показываются до фильтра операции, selected — после всех фильтров.
Возвраты и РЦ исключены. Начисления — известное bonusInc (к начислению), списания — bonusDec.
availableBonusInc не подставляется вместо bonusInc. Баллы не конвертируются в рубли.
Для среднего используются только покупки с известной суммой; число неизвестных сумм отдельно.
Данные читаются порциями по 200 записей в транзакции, в память не загружается вся история.
Номера карт, контакты и raw_json не выдаются помощнику. Загрузка Saby не запускается.

Новые инструменты помощника: count_checks_by_amount, search_purchases, get_purchase_card.
Все запросы читают локальную БД, без Saby и изменений данных. Доступ через существующего
авторизованного помощника. РЦ и удалённые продажи исключены.

Примеры проверки:
- Сколько покупок больше 500 рублей в октябре 2026 по всей сети?
- Сколько покупок от 500 до 1000 рублей в Батумской за октябрь 2026?
- Покажи 10 самых крупных покупок за октябрь 2026 по сети.
- Покажи покупки с пакетом майка в Батумской за 1–4 сентября 2026.
- Найди продажу номер 25529 за 23 октября 2026 на Шоссе Космонавтов 115а.
- Покажи состав этой покупки и её оплаты.
- Покажи возвратные продажи Батумской за октябрь 2026.
- Покажи следующую страницу.

Сумма — retail_sales.total_price. Идентичность — пара point_id + sale_id. Одна продажа
может иметь несколько платёжных записей; они не увеличивают число покупок. Это не
гарантированное число фискальных чеков. Номер продажи и номер платёжного чека различаются.
Номер ищется точно по исходному Number с fallback sale_number, без подстановки во внутренний ID.
При нескольких совпадениях необходимо выбрать магазин/продажу, а не первую строку.

count_checks_by_amount поддерживает строгие и включительные границы и равенство.
search_purchases использует включительный диапазон. Период до 92 дней; даты включительно.
Аналитика использует бизнес-день; поиск номера по дате — календарную дату эффективного
времени чека в Asia/Yekaterinburg. Время открытия может отличаться: при отсутствии результата
уточнить дату, не утверждать отсутствие продажи в Saby.

По умолчанию ищутся покупки без возвратов, returns=true ищет только возвратные продажи.
Это не поиск всех продаж с частичным возвратом: такие записи можно увидеть в оплатах карточки.
Фильтр товара использует обычные товарные строки, игнорирует refused; не ищет вложенные
модификаторы. Учётка и смена берутся из продажи Saby, не из графика Core.

Сортировки: amount_desc, amount_asc, recent. По 1–50 покупок, стабильный порядок по
point_id/sale_id при равенстве, offset до 10000. Итог total_matches не ограничен страницей.
Карточка показывает до 50 строк товаров и оплат отдельно, next_offset для продолжения.
Не суммировать вложенные товарные строки, оплаты и сумму покупки между собой.
Контакты, номера карт и raw_json не передаются агенту. Бонусы не выводятся из скидок.
Результат по пустому периоду не подтверждает отсутствие продаж в источнике.

CSV для этих новых инструментов пока не поддерживается; контекст старого CSV сбрасывается.
Реальные серверные результаты проверяются после отдельно согласованной сборки и установки.
