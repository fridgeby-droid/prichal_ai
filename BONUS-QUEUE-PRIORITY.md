# v0.3.37 — новые продажи перед повторной проверкой ошибок

После установки продолжите существующий общий запуск:

```console
python -m scripts.saby_data resume
```

Новый порядок действует также для `python -m scripts.bonuses load --all`:

1. Продажи с клиентом, для которых ещё нет бонусного наблюдения.
2. Только при явном --refresh — ранее обработанные ответы, выбранные для перечитывания.
3. Ранее ошибочные продажи, начиная с самого старого attempted_at. После новой неудачной попытки время обновляется, поэтому в следующем запуске запись перемещается за другие, давно не проверенные ошибки.

При обычном запуске успешные ответы пропускаются. Ошибка текущего прохода не выбирается повторно в этом же проходе. Отдельной команды для второй очереди не требуется: загрузчик переходит к ней после новых записей. При непрерывном поступлении новых продаж очередь ошибок может откладываться до их обработки.

Защита сохранена: пять ошибок подряд, ошибка авторизации или ограничение запросов останавливают загрузку. Это может случиться и на новых продажах, если Saby действительно не отвечает. Ошибки остаются неподтверждёнными, не превращаются в нули. PARTIAL_ERRORS не объявляется полным успехом; завершённые этапы общего запуска не повторяются.

`python -m scripts.bonuses plan` теперь показывает queue_order=NEW_FIRST_THEN_OLDEST_ERRORS. Прогресс и таблицы не сбрасываются. Установка сборки сама не запускает загрузку. Не запускайте второй процесс параллельно работающему.

306 локальных тестов прошли, включая выполнение выражения сортировки на тестовых записях, перемещение повторно ошибочной записи в конец очереди ошибок и существующие проверки массового сбоя. Рабочая PostgreSQL и ответы Saby здесь не проверялись.
