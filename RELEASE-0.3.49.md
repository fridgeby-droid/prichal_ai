# Причал AI 0.3.49 — управленческий помощник

## Что добавлено

1. Память диалога: последние 12 сообщений (до 6000 символов каждое), выбранная область и фильтры последнего поддерживаемого отчёта. Хранится в существующей PostgreSQL `app_meta`, отдельно для пользователя, чата и темы Telegram. Срок — 7 дней с последнего обновления, просроченные записи удаляются при следующем сохранении. Сырые ответы Saby и CSV не сохраняются в памяти. `/newdialog` очищает контекст. Диалоги одного пользователя в одной теме выполняются последовательно в одном процессе приложения.
2. Разбор отклонений: сравнение выручки/платежей/среднего чека, смен, товаров, категорий и дневной динамики. Код рассчитывает арифметические вклады числа платежей и среднего чека в изменение итога и среднего за день. Это не доказательство коммерческих причин.
3. Карточка магазина: сравнение с базой, динамика, клиенты и покрытие бонусными ответами.
4. Утренний обзор: `/morning` либо обычная просьба. Код выбирает последний закрытый бизнес-день по настройкам часового пояса и границы 08:00; сравнивает с тем же днём недели неделю назад. Автоматическая рассылка по времени в этой версии не включена: адресаты и время ещё не согласованы.
5. Сравнение учёток по магазину, дню недели и дневной/ночной смене. Показываются покупки, наблюдаемые дни и показатели остальных учёток той же группы. При отсутствии базы — NO_PEERS; менее 30 своих/30 чужих покупок либо 3 наблюдаемых дней — LOW_SAMPLE. Это эвристические ограничения отображения, не тест статистической значимости. Реальный график и трафик не подключаются этим пакетом.
6. CSV по обычной просьбе: детальные отчёты товаров, модификаторов, клиентов, средних чеков, динамики и расширенной аналитики. Сохраняются фильтры, экспортируются все строки, а не первая страница. Максимум 3 файла за ответ и 45 МБ на файл. Файл пересчитывается по локальной БД с прежними фильтрами; это не зафиксированная копия старого результата. При смене области прежний файл автоматически не подменяется. Для составного обзора агент сначала выбирает нужный детальный отчёт.

Разделы составных обзоров читаются последовательно, отдельными запросами: это не единый атомарный снимок. Ошибка одного раздела возвращает `complete=false` и перечень недоступных разделов. Состояние загрузки/сверки остаётся в исходных результатах. Прямых запросов Saby новые обзоры не выполняют.

## Установка и проверка

Обычное обновление архива Bothost. Дополнительные зависимости, миграция схемы и повторная загрузка чеков не нужны. Нужны действующие настройки PostgreSQL и OpenAI. Никаких действий в Core или изменений расписания загрузки.

Проверить версию:
```
python -c "print(__import__('app.version',fromlist=['APP_VERSION']).APP_VERSION)"
```

Сценарии Telegram — выполнять последовательно:

- `/newdialog`
- «Сравни Батумскую 5: октябрь с сентябрём 2026».
- «А отдельно по ночной смене?» — магазин и периоды сохраняются; данные перечитываются.
- «Почему снизилась выручка Батумской 5 в октябре к сентябрю 2026?» — факты, гипотезы и предложения разделены.
- «Покажи карточку Батумской 5 за октябрь 2026».
- `/morning` — проверить даты закрытого дня и базы неделей раньше.
- «Сравни учётки продавцов Батумской 5 за октябрь 2026 в одинаковых условиях» — малые выборки не ранжируются как доказательство эффективности.
- «Клиенты по сети, не покупавшие 30–59 дней на 31 октября 2026; история с 1 июля».
- «Пришли этих клиентов файлом» — получить CSV всех строк той же группы, а не только страницы.
- «Покажи средний чек по учёткам Батумской 5 за октябрь 2026», затем «Пришли CSV».
- `/newdialog`, затем «А ночью?» — помощник должен уточнить область и период.

Фактическая отправка Telegram и ответы модели проверяются после установки. Локальные автоматические проверки используют подставные ответы сервисов и не обращаются к боевой БД, Saby или OpenAI. ZIP не является установкой на сервер.
