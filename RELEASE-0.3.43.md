# Причал AI 0.3.43 — автоматические обновления источников

## Включение на Bothost

Установить архив, сохранив секреты, переменные окружения и собственные настройки.
Базу не очищать, backfill №6 не повторять. Предыдущий общий запуск с бонусными
ошибками можно оставить в истории: он не блокирует новый автоматический цикл.
Дождаться окончания ручных загрузок перед перезапуском приложения.

```env
AUTO_SYNC_ENABLED=true
AUTO_SYNC_ON_START=true
AUTO_SOURCES_ENABLED=true
SYNC_INTERVAL_MINUTES=60
SYNC_RECENT_DAYS=3
AUTO_BONUS_BATCH_SIZE=50
AUTO_BONUS_INTERVAL_MINUTES=10
AUTO_SOURCE_INTERVAL_HOURS=24
SABY_PRICE_LIST_POINT_IDS=23109
```

Перезапустить приложение. Это запускает работника внутри приложения, отдельный
процесс, cron или команда resume не нужны. 2 ГБ памяти достаточно учитывать как
новый лимит размещения, но лимиты запросов Saby сохраняются. В этой версии задания
выполняются последовательно, чтобы не конкурировать за лимиты Saby.

По умолчанию AUTO_SOURCES_ENABLED=false: обновление кода само по себе не включает
новые обращения к Saby. AUTO_SYNC_ENABLED=false останавливает весь автоматический
цикл. Если AUTO_SOURCES_ENABLED=false, работает только расписание продаж.

## Порядок и расписание

1. Продажи всегда имеют приоритет среди готовых заданий. Используется существующий
   sync_recent: продажи, платежи, позиции и смены за SYNC_RECENT_DAYS. После ошибки
   повтор через 5 минут. Фоновые задания ждут успешного цикла продаж.
2. Бонусы — только ещё не обработанные продажи с Customer, до 50 чеков или примерно
   120 секунд на порцию. Проверка времени между чеками, текущий запрос с повторами
   может закончиться позже. Общий предел задания 300 секунд. При заполненной
   порции следующая попытка через минуту, при исчерпанной очереди — через 10 минут.
   Новый запрос не повторяет ранее сохранённые OK/UNSUPPORTED.
3. Магазины, каталог и прайсы — каждые 24 часа от успешного завершения (не в
   фиксированное время суток). При первом включении — после продаж. Каталог
   публикуется только после полной загрузки. Его предел выполнения 20 минут;
   при прерывании прежний снимок сохраняется, повтор начинает выгрузку заново.
4. Прайсы — сначала полный список, затем по одному полному прайсу за шаг. Между
   шагами работник проверяет очередь продаж. После перезапуска успешно сохранённые
   прайсы текущего запуска пропускаются. Нет настроенных точек — задание не
   планируется; изображения сохраняет Core по существующему контракту.
5. Бонусные ошибки — отдельное задание раз в сутки, до 10 записей. Выбираются только
   ошибки с последней попыткой более 24 часов назад, старейшие первыми. Любое
   готовое обычное задание имеет приоритет над этой очередью. Ошибки не удаляются
   и не объявляются нулевыми бонусами. При ошибке новые чеки остаются отдельной
   очередью и не ждут завершения старой.

Интервалы считаются от завершения задания; проверка расписания раз в минуту.
Готовые фоновые задания выбираются по давности ожидания, чтобы большой остаток
бонусов не мешал справочникам. Продажи не прерывают уже выполняющийся запрос:
в частности, обновление каталога может задержать их до 20 минут. Успешная загрузка
продаж не является подтверждением абсолютной полноты Saby.

Автоматический цикл сохраняет расписание и результаты в app_meta. Перезапуск не
перечитывает успешно обновлённые суточные источники раньше срока. Незавершённое
задание возобновляется с доступного сохранённого состояния; каждый бонусный ответ
фиксируется отдельно. Для каталога сохраняется целый снимок, не каждая страница.

Обычный sync_recent не закрывает автоматически длинный простой больше
SYNC_RECENT_DAYS. После такого простоя проверить check и отдельно загрузить
недостающие закрытые дни командой sales --all-history при выключенной автоматике.

## Проверка

```sh
python -c "print(__import__('app.version',fromlist=['APP_VERSION']).APP_VERSION)"
python -m scripts.saby_data check
python -m scripts.bonuses plan
```

В check → automatic_updates → maintenance:saby:scheduler:v1:

- sales — продажи;
- bonuses_new — новые бонусные ответы;
- stores, catalog, prices — справочники;
- bonuses_errors — отложенные повторные попытки.

Каждое задание содержит status, started_at, finished_at, last_success_at,
next_run_at и последний результат/безопасный код ошибки, когда они доступны.
OK — последняя порция или обновление успешны, не полнота всей истории бонусов.
PENDING у прайсов — есть следующие прайсы текущего запуска.
ERROR — запланирован отложенный повтор. INTERRUPTED — остановка приложения.
RUNNING без движения времени/счётчиков не доказывает работу процесса.

component_updates остаётся историей ручных запусков; старый maintenance: ERROR
не означает ошибку нового автоматического работника. Следить за automatic_updates
и счётчиками bonuses. Исторические 135 ошибок остаются видимыми до успешной обработки.

В журнале: `Automatic source update started/finished`, имя задания и результат.
Полный журнал карточек клиентов, номера карт и секреты в статус не записываются.

## Ручное обслуживание

Выключить AUTO_SYNC_ENABLED и AUTO_SYNC_ON_START, перезапустить и использовать
команды из RELEASE-0.3.42.md. Не запускать несколько обновлений вручную.
Новый общий замок обслуживания защищает также отдельную команду bonuses load:
если другое задание занято, она вернёт MAINTENANCE_ALREADY_RUNNING. Блокировки
принудительно не снимать. Несколько экземпляров автоматического работника
координируются через PostgreSQL; запросы не дублируются между ними.

Принудительная перезагрузка старых чеков, payroll, Core schedule и подключение
счётчиков трафика в этот выпуск не входят. API Core и S3 сохранены.

## Проверки выпуска

Тесты проверяют приоритет продаж, отсутствие фоновой работы после ошибки продаж,
раздельные очереди бонусов, суточную отсрочку ошибок, сохранение расписания,
прерывание/возобновление, пошаговую загрузку прайсов и блокировку второго работника.
Живой доступ к Saby/серверу не использовался. Установку и первый цикл проверяет
владелец на своём сервере.
