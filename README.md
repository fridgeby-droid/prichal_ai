# Причал AI v0.2.9 — Adaptive Sync + Return Fix

## Исправление 1: полная выгрузка Saby

`retail/order/list` больше не обходится обычным `page=0,1,2...` как основной механизм.

Для каждой точки и календарного дня бот:

1. запрашивает интервал с `pageSize=100`;
2. если вернулось меньше 100 продаж — интервал считается полным;
3. если вернулось ровно 100 — временной интервал делится пополам;
4. половины запрашиваются рекурсивно;
5. результаты дедуплицируются по `Sale`/`Key`.

Это предотвращает и бесконечную пагинацию, и тихое обрезание продаж после первых 100 записей.

## Исправление 2: возвраты в ShiftEngine

В v0.2.7/v0.2.8 `sale_payments.signed_amount` уже был отрицательным для возврата, но ShiftEngine затем применял `abs()` и фактически превращал возврат обратно в положительную сумму.

Теперь отрицательный payment ledger row передается в ShiftEngine как `is_return=True`, поэтому сумма смен корректно уменьшается.

## После деплоя

На время проверки:

```env
AUTO_SYNC_ENABLED=false
AUTO_SYNC_ON_START=false
```

Затем сделать чистую загрузку:

```text
/resetdata confirm
/sync 3
/reconcile 2026-09-19
/shifts 2026-09-19
```

Для контрольной Батумской ожидаем сравнение с фактом:

- DAY: 19 307,55 ₽
- NIGHT: 78 852,33 ₽
- TOTAL: 98 159,88 ₽

Если после полной adaptive-выгрузки payment ledger все еще не совпадет с этими цифрами, следующий шаг — сравнение конкретных полей Saby (Amount vs tender sums vs TotalPrice), а не дальнейшая сменная логика.
