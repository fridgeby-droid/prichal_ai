# Справочники Причал AI → Причал Core

Статус: включено в сборку v0.3.12 вместе с /daily. На сервер автоматически не устанавливалось. График, зарплата и запись связей в Core не реализуются этим API.

## Подключение

Один запрос отдаёт магазины и учётки продавцов из одного согласованного снимка базы:

```http
GET /api/v1/core/directories
Authorization: Bearer <отдельный ключ интеграции>
```

На сервере AI задать `CORE_DIRECTORY_API_KEY` — отдельную случайную секретную строку не короче 32 символов. Пустое значение или значение короче 32 символов отключает API. Core хранит тот же ключ только на своём сервере. Запросы выполнять по HTTPS с сервера Core, не из браузера и не через языковую модель. Не использовать ключ Saby или Telegram. Ключ в URL не передавать. При смене ключа обновить настройки обеих сторон и перезапустить AI.

Другие существующие маршруты приложения этим ключом не изменяются. API только читает данные, не запрашивает Saby и не меняет связи сотрудников.

## Ответ 200

```json
{
  "schema_version": 1,
  "generated_at": "2026-10-09T12:00:00Z",
  "last_successful_sync_at": "2026-10-09T11:59:00Z",
  "scope": "retail_excluding_rc",
  "seller_source": "observed_saby_payment_accounts",
  "complete_snapshot": true,
  "store_count": 1,
  "seller_count": 1,
  "stores": [
    {
      "saby_point_id": "5598",
      "name": "Яблокова 14",
      "address": "",
      "locality": "",
      "updated_at": "2026-10-09T11:59:00Z"
    }
  ],
  "sellers": [
    {
      "saby_seller_id": "5686",
      "display_name": "Сексяева Е.В.",
      "observed_names": ["Сексяева Е.В."],
      "first_seen": "2026-07-01",
      "last_seen": "2026-10-08",
      "stores": [
        {"saby_point_id": "5598", "first_seen": "2026-07-01", "last_seen": "2026-10-08"}
      ]
    }
  ]
}
```

Пример иллюстративный: даты и количество не являются выгрузкой рабочей базы.

- Все Saby ID — строки, чтобы не терять точность BIGINT в JavaScript. Это исходные ID Saby, не внутренние ID identity map.
- Снимок полный для текущего набора данных AI, без пагинации и без скрытого лимита; это не гарантия полноты кадрового справочника или истории Saby.
- Магазины берутся из retail_stores, РЦ 23109 исключён. Отсутствие продаж не удаляет магазин из справочника.
- Учётки берутся из платёжных записей неудалённых продаж по включённым магазинам. Учётка, встречавшаяся только на РЦ, отсутствует. Записи без seller_id не экспортируются: стабильной привязки для них нет.
- Одинаковое имя с разными ID даёт разные записи. Варианты имени одного ID перечислены в observed_names. display_name выбирается по наиболее поздней business date появления имени; при равенстве дат выбор алфавитный. Это наблюдаемое имя, не подтверждённое юридическое ФИО.
- Учётка без имени остаётся в списке с display_name=null и пустым observed_names.
- first_seen/last_seen — границы наблюдений в загруженной истории по бизнес-дате, не даты приёма/увольнения. Могут быть null. Магазины учётки означают наблюдения, а не кадровое закрепление.
- generated_at — время формирования ответа. last_successful_sync_at — время последнего успешного запуска загрузки (может быть null); это не подтверждение, что после него не было ошибок или что все даты загружены.
- Адрес и населённый пункт могут быть пустыми. Телефон, табельный номер и кадровый статус не предоставляются.
- Возвраты и fallback-записи тоже могут содержать наблюдения учёток. Привязка учётки не доказывает фактического автора каждого чека.

## Обработка в Core

1. Получить снимок серверным запросом, проверить schema_version=1 и счётчики массивов.
2. Сохранить локальную копию целиком в транзакции. При ошибке сохранить предыдущую копию и отметить неудачную попытку.
3. Показать варианты сопоставления по имени/адресу. Сохранять подтверждённые администратором связи с ID, не автоматически по ФИО.
4. Не удалять подтверждённые связи при пропадании записи из следующего снимка. Пометить «нет в последней выгрузке» для проверки. Пустой снимок не означает увольнение всех сотрудников.
5. Источник истины для подтверждённых соответствий — Core. Поле core_employee_id в AI этим API не заполняется; двустороннего обмена связями пока нет.
6. Сотрудники, которых нет в Saby, включая ночных помощников, остаются только в Core. Общая учётка сохраняет исходную атрибуцию продаж; исправления фактического исполнителя требуют отдельного решения.

## Ошибки и проверка

- 401: ключ отсутствует или неверен; тело не содержит справочников.
- 503 `Directory API is not configured`: ключ на AI пустой/короткий.
- 503 `Directory data temporarily unavailable`: ошибка чтения БД. Core не очищает сохранённые данные.
- Cache-Control: no-store на ответах API, включая ошибки доступа.

После будущего развёртывания проверить 401 без ключа, затем 200 с правильным ключом, отсутствие 23109, список вариантов имён и даты активности. Число магазинов ожидается 12 для текущего набора, количество учёток может отличаться от ранее созданных 78 identity-записей.

Локальные тесты не обращаются к рабочей PostgreSQL и не запускают Telegram polling. В тестах проверяются доступ, выключенный API, скрытие деталей ошибок, точность ID, тёзки, смена имени, отсутствие имени, исключение РЦ/удалённых продаж/записей без ID.
